# 图片规划与排版交付记录

## 本轮核查

本地 77a8ea8 与远端 d2be2d9 内容一致，保留 DeepSeek 完成的数量判定、reference 高档和 text_mode 协议。其四项 CI 通过能证明编译/测试，不足以证明视觉质量。

确认的问题：

1. 旧文字排版字号固定为 13–34 点，在 2K 画布上过小；单栏从左上角连续绘制，模型没有可表达的文字区域协议。
2. 底图生成前不知道后续文字占用的区域。即使模型画得好，后处理也可能覆盖主体。
3. UIKit 默认设备倍率会把 2K 底图重新输出为 4K/6K，增加内存却不增加细节。
4. text_mode 被放在 context 之外，派生/重试容易漏传。现由不可变上下文保存，底图派生设置 overlay。
5. 成功排版立刻删除底图，与“只改文字不重新生成”的目标冲突。现在按 TTL、容量、会话/账号生命周期回收。
6. DeepSeek 修复了单图误判组图，但组图 resolveCount 仍可能把“四个人”当四张；现张数解析统一只认图片量词。
7. 服务端 overlay 在空 prompt 的旧结构化兜底仍会拼回文案；现兜底同样受 includeText 控制。原生文字模式不再被 flat_artwork 品类暗中覆盖。

## 采用的成熟方法

- [Anthropic canvas-design](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)：参考其先明确设计方向、再组织构图/层级/留白的方法。未复制全文、未安装外部代码；自行编写适配本 App 的简短 ImageDesignGuidance。用户指定动漫风、完整客户文案等要求优先，不套用该 skill 的固定艺术偏好。
- [Polotno 设计格式](https://polotno.com/docs/schema)：文字作为带稳定 key 和几何区域的独立元素，模型规划后验证再渲染。
- [Polotno 文字尺寸](https://polotno.com/docs/text-sizing)：按文本框、字号上下限测量适配。使用 iOS 现有字体测量/绘制能力，不引入 Web 编辑器依赖。完整文案放不下时明确失败并保留底图，不截断。
- [IMG.LY 设计自动化](https://img.ly/docs/cesdk/vue/automation/design-generation-98a99e/)：参考视觉资产与文字占位区域分离的工作流。

## 当前完整路径

用户与附件 → Agent 设计判断及 typed text/layout → 来源解析与画布规划 → TextLayoutPlanner（归一化区域）→ 同一区域生成无字底图 → 同一区域测量/一次叠字 → 产物落库。

无精确文字任务继续走直接生成/编辑。自由排版使用 layout.blocks；缺失、重叠、越界或不完整的模型布局统一退回通用构图，不丢任何文案。默认构图根据横竖画布组织标题、主视觉、信息带与页脚，字号随短边缩放。新增设计指导仅作用于前置图片规划，不再增加服务端二次 LLM 改写。

## 验证与边界

新增横竖构图、字体缩放、区域覆盖、冲突回退、底图区域约束不含客户文案、文字模式派生、精确像素输出等回归。iOS 测试附带 PNG 视觉样张，CI 导出后人工查看。后端测试纳入 IPA 发布门禁。

第一轮视觉检查确认无重叠、字号层级正确，但自动对比底层铺满文本区域，形成不必要的大块深色面板；已改为采样文字下方底图的亮度对比，仅在不足时按真实文字高度补局部底层。字体支持 sans/serif/rounded，测量与绘制使用同一字体配置。

比例一致仍不能证明模型完整保留原图主体；风格遵从与真实人像编辑需要实际素材验证。审美指导改善规划输入，不等于对每张随机结果作质量保证。整个 App 的 B/C/D 架构迁移继续以 ARCHITECTURE-REFACTOR-PLAN.md 为基线，未冒称本轮已重写全 App。
