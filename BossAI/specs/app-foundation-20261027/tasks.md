# 全 App 优化执行计划与验收表

日期：2026-10-27；基线 `c662714`。本文所有勾选框均为待实施，不能作为完工记录。
配套：[需求与产品边界](requirements.md)、[源码审查、架构和成本设计](design.md)。

## 一、执行顺序

“先底座”不等于先把全仓重写：先补齐公共错误、任务、数据接口，再用图片这条最重要的能力完成首条闭环，随后迁移其他工具。每个阶段独立可验证，整体按同一份计划连续执行，不以等待上一轮 CI 为由停止所有独立工作。

| 顺序 | 优先级 | 阶段与用户收益 | 主要改动 | 依赖 | 验收门槛 |
|---|---|---|---|---|---|
| 0 | P0 | 锁定事实，保留现有可用功能 | 当前 commit/远端/线上配置/旧客户端接口清单；测试基线；数据备份与回滚点 | 无 | 当前各域可运行情况有记录；不覆盖 DeepSeek 变更 |
| 1 | P0 | 报错能理解、能查到 | 统一业务错误/trace/job/上报队列；修工具事件丢字段及假确认 | 0 | 断网错误补报、同事件去重、按 requestId 能串起客户端与服务器 |
| 2 | P0 | 图片/文件生成后不会因重登丢失 | Asset/Artifact 契约、自有对象存储归档、签名 URL、恢复读取；补旧图迁移入口 | 0、1 | 换设备能看到同一原图；归档失败只重试归档 |
| 3 | P0 | 会话同步可靠且省流量 | outbox、分条消息/目录分页、服务端提交游标、版本冲突、删除、账号切换 | 1、2 | 两设备、断网、时钟偏移、长对话、删除不复活全部通过 |
| 4 | P1 | 整个 App 的执行规则一致 | ToolManifest、Dispatcher、ChatTurnRunner、领域 UseCase；后端同域抽离 | 公共接口在 1–3 固定；纯抽离可并行 | 每个现有工具有唯一声明及入口；搜索/文档/图表/附件均可完成和恢复 |
| 5 | P1 | 三类图片任务及比例完整可用 | 原生优先调用、edit/reference 分流、尺寸契约、预览/缩略图；审查 c662714 优化开关假设 | 1–4 | 文生、局部编辑、重设计各有真实样例；9:1/1:9 可表达且不被 UI 裁切 |
| 6 | P1 | 降低重复存储与无效付费 | 账号内去重、图片变体、按需下载、缓存、孤儿清理、预算指标 | 2、3；成本观测从 0 开始 | 同一资产重复保存不增对象；列表不拉原图；无误删、无静默降质 |
| 7 | P2 | 需要时才扩展复杂能力 | 精确文案工作流、完整图层、改进混合路由、设计参考按需注入 | 核心闭环与固定素材验收 | 不干扰普通原生调用；每个新增分支有独立质量和成本证据 |
| 8 | 发布门禁 | 一个可追溯交付包 | 交叉审计、线上灰度/回滚、CI、IPA、迁移报告 | 该发布范围所有阶段通过 | 源码/部署/CI/IPA 版本一致，未测项如实列出 |

说明：阶段 7 的混合路由必须晚于质量验收；完整图层可作为后续独立交付，不用它阻塞账号与历史图片恢复。具体人日需阶段 0 确认活跃旧版、数据库索引与线上资源后估算，不给“几小时全 App 无 bug”的不实承诺。

## 二、可直接执行的任务清单

### P0：公共可靠性与数据闭环

- [ ] T00 建立现状清单：本地/远端 hash、实际部署包/配置、关键接口调用方、现有测试与可回滚版本；只读检查套餐、对象存储权限/容量、索引与任务触发器。_R01、R15_
- [ ] T01 定义 AppError/TaskResult/ArtifactRef/AssetRef 最小公共协议，区分生成、保存、下载、同步、账务；现有 APIErrorEnvelope 兼容映射，不建立第二套竞争错误表。_R03、R06、R07_
- [ ] T02 修服务端工具事件接收和持久化回执；接上 trace/request/job/build/stage；白名单脱敏、上报幂等、离线队列有界；不因上报失败中断主功能。_R06_
- [ ] T03 统一 UI 错误展示与动作映射，移除“所有失败都一句重试”的限制；本地保存失败不向用户透出系统异常原文。_R03、R06_
- [ ] T04 在现有 COS 凭证链上实现资产登记/完成/签名/删除接口，持久化 owner、MIME、hash、尺寸和对象键；上传后验证，授权按账号与对象归属检查。_R01、R02、R14_
- [ ] T05 建立生成资产归档与有限重试/对账；保存原生成结果、组图每张、客户端叠字成品；归档失败保留任务，不触发模型再生成。_R03、R13_
- [ ] T06 消息与资料库共用 Artifact/Asset；显示本地已保存/云端待同步/已同步；临时签名到期自动重签，磁盘缓存 miss 自动下载。_R02、R03_
- [ ] T07 实现增量 outbox 和消息级 upsert，分条/按字节批量；禁止整段 JSON 截断；兼容旧会话快照协议。_R04、R14_
- [ ] T08 用服务端提交游标替代本机 Date；固定分页水位、落地后推进，恢复未确认批次；异步迟到写入不能遗漏。_R04_
- [ ] T09 登录/恢复网络/本地提交/前台切换触发同步，节流合并；切账号取消旧任务并固定 session owner；未知同步类型具备明确版本兼容策略。_R01、R02、R04_
- [ ] T10 对话/消息/附件/记忆的版本合并与删除规则；并发编辑保留双方消息；云端墓碑、离线补删及资产引用解除协调，不删除仍被引用的作品。_R04、R05_
- [ ] T11 迁移老图片与文件，保留老字段双读；当前设备有副本则可补传，确认归档后才清理重复本地大对象；无法恢复的旧图明确标识。_R02、R15_

## 三、必须覆盖的验收矩阵

| 类别 | 场景 | 通过条件 |
|---|---|---|
| 身份 | A 上传/生成中切 B，再切回 A | 无跨账号读写；旧请求不污染 B；A 可恢复自己的任务 |
| 数据恢复 | 新设备登录，或清空本地缓存后重新登录 | 会话文字、单图、组图、附件、资料库可恢复；原图内容 hash 对应同资产 |
| 历史迁移 | 旧版本地 imageData、extraImagesJSON 和 StoredFile | 可迁移部分成功入云；原图无副本部分如实标记；不伪造恢复 |
| 增量 | 两设备离线分叉/先后登录、同 ID 修订、时钟快慢、延迟上传；若开放多端在线再测同时写入 | 不丢双方消息、修订和后来补齐的图片引用；不绕过现有 session 撤销规则 |
| 大会话 | 长正文、超 400K 会话、多页目录和消息 | 不截断 JSON，不一次传所有原图，不无限同步失败 |
| 删除 | 离线删会话，另一设备仍在线更新 | 墓碑/版本规则收敛；无复活；共享资产未被误删 |
| 归档故障 | 模型成功后 COS 不可用/签名过期/客户端断线 | 重试保存或换签，不重新生图；账务状态不伪报 |
| 幂等 | 首次超时、同 requestId 重试、App 重启再查 | 能查询原任务，状态明确；对未知上游结果不保证零费用而直接重发 |
| 错误上报 | 断网失败后重启联网、重复上报、写库失败 | 真实回执后出队；可检索 trace；无敏感内容，无自循环 |
| 聊天 | 断流、取消、长会话、切后台 | 输入与已完成消息保留；无重复消息、无假完成 |
| 搜索 | 网络失败/无结果/引用不足 | 明确未核实，不伪造来源 |
| 文档/图表 | 生成/导出/打开/历史恢复 | 文件实际有效，资料库及历史指向同产物 |
| 文生图 | 纯插画、短标题海报、中文信息海报 | 原生能力正常，文案不被误当视觉 prompt 上屏，精确要求走正确分支 |
| 局部编辑 | 加人物、换背景、换衣；多图指定第二张 | 原图选对；保留目标与修改范围可追踪；不误变成多张生成 |
| 重设计 | 上传海报“不要蓝色科技风，换动漫风和布局” | 走参考重设计；允许重排；指定内容与禁止项被真实检查 |
| 尺寸 | 1:1、4:3、3:4、16:9、9:16、3:1、1:3、9:1、1:9＋EXIF 旋转 | 请求合法、输出容差合理、缩略图/预览不中心裁切；无法满足明确提示 |
| 组图 | 部分生成、部分下载失败、恢复/取消 | 顺序与状态准确，只恢复对应子任务/下载，不重生成成功项 |
| 图层（开放时） | 1 底图＋多 PNG、换签、重登、导出 | 不丢层、不丢透明通道；位置和 z_index 可还原 |
| 成本 | 重复保存、频繁进列表、长历史同步 | 对象不重复、列表主要缩略图、同步传增量；可测算 GB 与流量 |

## 四、实施与发布规则

1. 同一阶段可独立工作的项连续完成，不为了文件数量拆成多轮等用户催促。逻辑提交可分，避免全部挤成不可审查的大提交。
2. 测试随边界迁移补齐：纯函数和协议测试本地先跑，Swift 编译按有效批次验证；正式候选包跑一次完整 CI，失败修复后重跑是必要验证，不受“只许一次 CI”约束。
3. 关键数据库/资产迁移先 dry-run 和备份；新写＋双读、灰度对账，保留旧接口兼容。不 reset 用户仓库、不强推、不覆盖另一代理的新提交。
4. 公共错误和资产/同步契约通过后，才迁移每个能力的执行器；不先做全仓文件搬家。
5. 每次上线列出源码 SHA、部署函数与版本、数据库兼容步骤、配置变更、CI run、IPA SHA256、通过/未测矩阵、回滚办法。
6. 不因“所有单测绿了”声称审美达标或零 bug。真实素材和两设备验收是发布范围内的独立门禁。
7. 本轮不触发部署或编译；以上是给用户审阅的完整实施方案。下一轮按确认的发布范围实施，不能把本计划中的待办写成现成功能。
