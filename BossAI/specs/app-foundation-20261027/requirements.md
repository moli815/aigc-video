# App 底座与图片链路收敛：需求与验收

日期：2026-10-27。审查源码基线：`c662714`，其前一提交为 `ecae9ba`。
状态：完整方案草案；本轮只审查、规划，不修改业务代码、不部署、不触发 CI。

## 1. 对用户目标的理解

产品是一个可持续使用的 AI App，图片是重点能力，但账号、对话、搜索、文档、附件、产物、错误恢复共同构成底座。优先顺序是：数据不丢与问题可定位 → 完整执行与恢复 → 原生图片能力 → 质量和成本优化。

Seedream 的原生提示词优化应优先使用；它提升输入利用与生成效果，不承诺每张图都达到专业设计成稿水平，也不替 App 处理账号、尺寸参数校验、状态恢复和文件保存。

“不报错”的可验收定义：合法输入能够走到明确终态；网络、额度、上游、存储等异常可恢复、可解释、可追踪，不假报成功，不让用户看到内部异常字符串。不能承诺外部服务永不失败。

## 2. 需求与验收标准

| ID | 需求 | 当……时，系统应…… |
|---|---|---|
| R01 | 账号会话隔离 | 用户切换账号时，取消旧账号同步与任务订阅；旧响应不得写入新账号数据，缓存和上传凭证不得串用。 |
| R02 | 云端恢复完整会话 | 用户在新设备登录同一账号时，恢复已同步的文字、附件引用、单图、组图顺序、任务状态和资料库索引；本地路径不存在不应造成永久空白。 |
| R03 | 产物可靠保存 | 模型已返回产物但归档或下载失败时，保留任务及已有产物引用，只重试保存/下载，不重新调用付费生成。 |
| R04 | 增量同步与冲突 | 两台设备同时新增消息、时钟不同或离线恢复时，保留双方消息；服务端提交游标决定增量边界，不以客户端当前时间跳过数据。 |
| R05 | 删除一致 | 用户删除会话或资料时，各设备最终收敛且不复活；仍被其他资料引用的对象不得被提前物理删除。 |
| R06 | 自然错误与追踪 | 发生失败时，界面显示真实原因类别和可执行动作，事件在恢复联网后可上报并关联请求、任务、阶段、版本；不得假称服务器已收到。 |
| R07 | 通用执行底座 | 聊天、搜索、图片、图表、文档均使用统一任务结果、错误、取消和产物契约；能力 schema、权限和执行入口来自同一声明。 |
| R08 | 文生图 | 用户自然语言提出设计需求时，前置模型整理必要意图，Seedream 原生生成；不强制二次 LLM 美化、OCR 或客户端文字叠加。 |
| R09 | 局部图生图 | 用户要求添加人物、换衣或局部修改时，准确传原图及编辑范围，默认保持源画布；不得丢图退化为文生图，不承诺区域外逐像素不变。 |
| R10 | 参考重设计 | 用户要求换风格、重排版、整体重做时，以参考创作为任务语义，区分必须保留的内容与允许重做的布局；不得误用局部编辑锁死构图。 |
| R11 | 多尺寸 | 用户明确指定比例时优先执行；未指定时按用途推断，普通编辑继承原图。覆盖 1:1、4:3、3:4、16:9、9:16、3:1、1:3、9:1、1:9；超出能力时说明边界，绝不静默改成方图。 |
| R12 | 精确文案可选链路 | 用户明确要求逐字不变时，提取原文、处理识别疑点，再选择原生验证或程序排版。OCR 不等于真实原文，不能保证识别 100% 正确；不要求每次都弹确认。 |
| R13 | 组图与图层 | 组图保存全部独立作品和顺序；图层保存底图、所有 PNG、位置与层级。二者不混淆，不把数组第一项当全部成功。 |
| R14 | 成本透明可控 | 列表只加载缩略图；原图按需下载，账号内去重，增量同步，有保留期和配额。不得为省钱擅自删除已保存作品或静默降低模型档位。 |
| R15 | 可复现实验与发布 | 同一素材、任务、参数版本可追溯；在型号未确认支持 seed 时不依赖 seed。CI、部署版本和 IPA 哈希对应同一交付记录，回滚保留新数据。 |

## 3. 默认产品决策（用于形成可执行方案）

- 继续使用现有 SwiftUI/SwiftData、CloudBase、腾讯云对象存储；先复用现有服务，不重写整个 App、不立即引入 Coze 托管平台。
- 质量评测期间保持 Pro；恢复混合路由是独立验收后的配置变更。
- 普通设计优先模型原生文字和构图；精确文案是显式能力，不再因“名片/海报”名称或字数单独强制走固定模板。
- 无需用户反复重填已有文案。只有识别不清、版本冲突或关键字段确实缺失且影响结果时才要求确认。
- 已生成并保存的成品不设置未经告知的短期自动删除；临时上传、中间产物、日志采用单独生命周期。
- “本地已保存”“云端同步中”“已同步”“同步待重试”必须有区别，不把暂存失败改写成整次生成失败。
- 先保留现有单设备在线会话政策；跨设备恢复不等于擅自开放多设备同时在线。历史数据读取/导出是否与会员到期解耦，实施前明确规则，建议允许读取本人已保存数据。

## 4. 完整交付边界

本轮计划覆盖全 App 的执行、数据、错误和图片边界。实施不以“全部搬到服务端”或“全部复制一个开源 Agent”作为目标。

验收同时包含代码测试、两设备恢复、固定图片真实调用及真机体验；编译通过仅代表编译通过。未执行的验收项保持未完成，不写成全链路无问题。
