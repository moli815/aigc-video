二、11-20 周五：止血与回退

11:25带图对话必然报错「暂时无法确认本次用量」

问题

你在 App 里发一张图，立刻报 BILLING_UNAVAILABLE，连试都进不去。

根因

shared/cost-budget-admission.js 的 upperBound() 第一行就是：只要 inputImages > 0 就返回 null；reserve() 拿到 null 直接抛错。而台账里 chat 的 inputImages 正是按图片段数统计的——**发图必然触发**。

做法

  • upperBound 不再因带图返回 null，改为按张数定界（每张 1500 token 预估）
  • 只把文本计入字节统计——base64 图片参与字节折算会把预估抬高几十倍，反而误判额度耗尽
  • 顺带修：usage-settlement.js 的跨周期分支原来「不扣费也不释放预留」，会把 0.164 的 hold 永久挂在账户上

效果

11:29 发布 → 11:33 补结算修复 → 实测 HTTP 200、chargeState=committed、实扣 0.005684。全量测试 980/980。

三、11-21 周六：文字层三条路

周六的核心问题是客户那句反馈：海报上的小字 100% 崩坏，出现「北海址小止眨·栗子现 40y」这类伪文字。主标题正确，说明/参数全糊。这一天把三条路都试了一遍。

路一：服务端真字体层（试了，否决）

做法

Seedream 只出「背景 + 主视觉 + 插画」，明确不出现任何文字；服务端用 satori + resvg + Noto CJK 渲染文字层，再用 pngjs 做 alpha 合成。

新增 poster-overlay.js（版式树 + 草图生成）、overlay-pipeline.js（管线）。

效果

文字 100% 正确、任意字号清晰、改文案不用重生图（成本 0）。但版式是服务端网格。

你当时的原话：「每个模块都是这种直接方形切割，一条竖线切割，就会感觉很割裂。然后你这个整体也仍然很不美」。
所以这条路默认关闭（IMAGE_COMPOSITION_POLICY.overlay.enabled=false），能力保留作兜底。

路二：极简提示词交给 Seedream 排版（成功，成为主线）

做法

压到 435 字，只给「用途 + 素材 + 画面 + 逐行文字 + 三条风格」，不写版式清单、不写坐标、不堆形容词。

效果

六款产品名、说明、价格、电话全部正确，而且模型自己排出了撕纸边缘、枫叶、手绘图标等设计元素。

这一步定下了整个方向：版式交给 Seedream，我们只说清「要什么、做什么、给了什么」，文字逐行列出即可。

配套：草图约束 / 去二维码 / 长文排版

事项做法与结论
草图约束 服务端出一张纯色块草图作参考图，Seedream 严格按草图重绘——解决了「分区比例偏差导致文字层对不齐」的问题。
去二维码 对比两条路：服务端 inpaint（免费）定位不准、有残留；Seedream 局部重绘（¥0.28 / 15 秒）完全干净、其他内容零改动。选后者，且这条能力可复用于「去掉某个模块」「换掉某段文案」。
长文全文排版 longformTree：标题带 + 多栏流式正文 + 首字下沉 + 引用块 + 页脚，500–1500 字可排，字号按内容量自适应。代码就绪，分流未接。

提示词里的句子来源
「品牌既定文案，逐字照写，不许换词」实测标题被改成「秋天的栗香」「用一颗面包温暖每一天」
「逐字照写、不得改动」+ 每个词加「」官方 Seedream 5.5 指南：要生成的文字放双引号中可提升准确率
「严格遵循网格系统：等高、等宽、对齐」StartAI《Seedream 5.5 海报提示词公式》原文
「没有实拍就画示意图，不要只摆文字」口腔场景无产品素材时卡片全变文字块
「名称与价格同一行」（价格粘进名称块）安防六款报价被整体省略
「不写超过 20 字的连续长段落」模型自己补 200 字品牌故事，全是伪字
「不写『二维码空位』这类占位说明」模型把占位标注当正文印出来
「向下自然过渡（渐隐、羽化，不要硬边横切）」你的原话：「直接方形切割，一条竖线切割，会很割裂」
