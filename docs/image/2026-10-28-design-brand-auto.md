# 设计审美、品牌保真与自动路由

用户目标：丰富海报的样式与排版；原样使用上传 Logo；增强验证后恢复 Pro/Flash 自动选择；等待动画只先做 B/C 粒子聚散预览。

## 已确认的问题

1. `ImageReferenceResolver.sourceOverride` 可能把 Agent 正确的 `both` 覆盖为 `last`。用户说“把你生成的海报 Logo 换成我们的”时，上传素材因此被丢弃。现在两源语义保持不变，明确排除某来源时仍以用户要求优先。
2. 把品牌图交给生成模型描画，不能保证图形、笔画和文字一致。即使两张参考图都传到，也不能把“像”当“原样替换”。
3. 既有六条样式参考来自 UI 风格库，只增加模板数量不能替代用途、内容密度、构图、色板、表现手法的组合判断。
4. 旧 auto 的缺省就是 Flash，缺少分类依据。现在前置模型给 fast/high 与有界理由，客户端守住身份、品牌与密集文案等高保真要求；服务端仍负责真实模型 ID 与能力，未知分类保守使用 Pro。

## 研究依据（2026-10-28）

- [Anthropic Canvas Design](https://github.com/anthropics/skills/tree/main/skills/canvas-design)：视觉层级、空间和构图意识；不直接导入其“艺术对象/稀疏文字”偏好，用户文案完整性优先。
- [JimLiu baoyu-cover-image](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-cover-image)：将色板、表现和情绪等维度分开组合。MIT 许可已记录；没有安装或执行它的脚本，没有把它的后端选择/确认流程加进 App。
- [JimLiu baoyu-infographic](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-infographic)：按内容关系选择结构，而不是任何信息都套成相同卡片。
- [Seedream 官方提示词/API说明](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)：中文视觉描述建议简洁；保留官方 standard 优化。Flash 是模型档位，Pro fast 是提示词优化模式，两者不能混为一谈。

参考词典从6项扩展为16项，中文指导为项目自行撰写。按用户当前风格只选最多4项，未指定则提供6项不同方向；不是每次注入全部技能和样式，不额外调用一次 LLM 改写。

## 品牌保真：独立后处理边界

`image_edit(source=both)` → 原底图 + 上传素材 → `structured.preserve_assets`（素材索引及目标区域）→ `PreservedAssetWorkflow` 校验 → 模型仅清理旧标识区域 → 原上传素材等比合成 → 默认恢复目标区域以外的原图像素 → 原 Artifact 保存链。

- Logo/二维码本身不交给模型重画；输入素材会按方向信息归一化，保留图形、文字和原始长宽比。
- 原始素材来自 resolver 后的第2张引用；原海报为第1张。缺来源、非法区域、互相重叠或过大的覆盖区，在付费调用前拒绝。
- 原样替换的明确语言不能在缺保真计划时退回生成式替换；工具可补齐参数后再执行。
- 只换 Logo 时，区域外像素来自原海报；用户同时要求其他区域编辑才允许保留模型对全图的修改。
- 清理底图在合成前缓存，按账号、完整背景意图和底图哈希隔离，15分钟/最多4条。合成失败复用底图；不把持久单图任务认领的旧待办宣称为已完成。
- 必须使用真实、清晰的原素材。拍屏照片、带白底的 JPG 不会被宣称自动成为透明矢量 Logo。自动推断替换区域仍需真实海报验收，不能仅靠坐标合法证明框选正确。

## 自动路由原则

| 场景 | 候选档位 | 守护规则 |
|---|---|---|
| 草稿、简单插画/图标 | Flash | Agent 必须给出明确低风险理由 |
| 简单背景改色 | Flash 候选 | 没有身份/品牌保真要求 |
| 人像、换装、动作、人物合成 | Pro | 不因“快点”静默降低保真 |
| Logo/二维码/品牌准确 | Pro + 原素材合成 | 不能用高档模型冒充素材保真 |
| 文案密集、复杂布局、正式终稿 | Pro | 内容与版式复杂度优先 |
| 用户明确最高质量 | Pro | 不自动降级 |
| 未分类或理由缺失 | Pro | 不把 auto 当廉价默认 |

路由决策记录 requestId、理由码、源图数量与比例，不上传提示词或原图；日志字段 `errorCode` 在这里承载事件理由，不表示生成失败。运行模式保持 pro_only，待本轮完整编译、行为验证与真实 Flash/Pro 调用后才按授权切 auto。故障不自动换档重复生成。

真实前置模型契约测试（使用 iOS 导出的工具定义和纯色合成夹具，不使用客户素材）：简单改色草稿正确返回 fast；品牌替换返回 source=both 及 preserve_assets，但辅助路由理由曾输出中文而非枚举。该非执行字段现在未知时移除，交由保守质量策略判定，不让可选元数据阻断任务。来源、素材、坐标等执行字段仍严格校验。首轮 CI a531ff2：355条 iOS 用例，7跳过、0失败；313条后端通过，随后补充真实契约所揭示的可选字段兼容回归。

待用户授权的独立事项：把当前生成图的一张压缩预览发送给前置聊天模型以定位编辑区域。自动审批认为这会新增图片的跨服务传输，已提出授权问题；本轮未增加该传输。看不清旧标识位置时仍需要明确区域，不能宣称自动定位全部完成。

最终修订 8b4d1ac 的 iOS 构建通过，但离线联网问答测试暴露测试隔离缺陷：`ResearchPipelineTests.vm` 注入了 chat/search，却漏注入 query planner，导致假测试密钥随 `completeOnce` 访问全局真实服务，偶发超过5秒；超时后旧任务还会污染下一条共享夹具。修复只落测试：使用已有 searchPlanner 注入点返回 nil（走确定性 seed 回退），超时时取消并等待任务结束后才继续下一条；不扩大测试时限、不删断言、不改生产联网行为。相关图片、保真合成和路由用例在该轮已通过，仍需最终全量门禁重新确认。

## 动画

新增 `outputs/BossAI-粒子等待动画-BC增强预览-20261028.html`：B 银白粒子、C 蓝紫星雾，180粒子/画布、约30fps上限，向中心汇聚后散开循环。支持横竖版、强度、深浅色、暂停、静态与成稿淡入演示。未改 Swift 等待组件，最终选择与实机测试结束后才加入。

## 验证边界

- 本地 Swift 语法检查不能替代 Xcode；以 CI 为准。
- 新增源图不丢失、原素材等比合成、区域外像素保留、缓存复用、缺参数不付费和多场景路由测试。
- 真实 Logo 的透明底、边缘、目标区域和成品审美仍需用户原始素材/实机对照，不保证生成模型永不产生错误。
