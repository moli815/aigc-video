## 本轮原则与实际范围

客户继续使用今天交付的已安装包，不要求下载或安装新IPA。仅更新 bf-api 的可选规划边界与配置说明；不修改 Swift，不更新 bf-image、不改会员/额度/同步/存储协议，不新增必填请求字段。

`IMAGE_LEGACY_BRAND_POLICY` 默认 `{"enabled":false,"accountIds":[]}`。只有 enabled 为布尔 true、且**鉴权后的内部账号ID**精确命中名单时才可能生效，不支持通配符、按比例全量开启或使用请求体传入的账号替代鉴权身份。

即使账号命中，也必须由手机实际声明 image_edit、both、source_index、source_indexes、reference_roles、library_refs、structured.preserve_assets/text 等现有能力，且当前任务明确涉及Logo/标识操作，才追加一条规划指引。无关任务和关闭状态返回原 messages 引用；工具定义、图片内容和工具执行参数不由本模块改写。该配置不放进 /me 的 appBehavior。

新增规划仍是候选功能，**客户账号未启用**，复杂抠图 Worker / 网页补充入口没有在本轮上线。不能把“兼容开关部署完成”说成“所有新Logo能力已经交付”。

## 旧包为什么不能直接接一张服务器成品

- PreservedAssetWorkflow 会保留原素材、移除 Provider 中对应素材，并在手机最后合成。服务器返回成品可能被二次贴图。
- preserve_outside=true 时手机恢复目标区域外原像素，服务器对这些区域的调整可能被覆盖。
- 添加Logo的 BrandPlacementPlanner 会按16%短边、5.5%边距吸附方位；不能用 Agent 原框推断最终避让效果。
- 两张上传图原样替换Logo存在旧包 both/attached 校验冲突。只有真实检索出的两个 library_refs 可走另一条既有原件路径；不能编造ID，不能把上传底图擅自换成上次生成图。

这些限制保留在候选指引中。没有新增旧包不认识的“关闭手机合成”标记，也不通过变更用户原话绕开校验。
