# Logo 与多素材工作流：开源调研及旧包适配判断

日期：2026-10-28。本文是调研和设计判断，不表示下列模型、容器或工作流已经部署。
约束：保留已寄出设备上的 App；不修改 Swift、不构建 IPA，不把新字段设为旧包必填。

## 结论

可以在服务器增加图片处理能力，但“服务端部署新能力”不等于“旧包所有入口都能使用该能力”。
必须先证明原图能到服务器、客户端会执行兼容的工具参数，并且不会在服务器成品上再次执行本地贴图。
纯改 prompt 无法替换本地写死的落位、抠图和参数校验算法。

## 核实过的开源项目

| 项目与官方来源 | 可复用能力 | 选择判断 |
|---|---|---|
| [rembg](https://github.com/danielgatis/rembg) | 背景移除，提供 Python、HTTP、Docker 入口，支持多种模型 | 适合包装成独立去底服务；不是 Logo 区域定位器。显式固定模型，不盲用默认权重 |
| [BiRefNet](https://github.com/ZhengPeng7/BiRefNet) | 高分辨率二分图像分割 | 可作为复杂去底候选；Logo 文字、细线、内部空洞要用实际素材验收，不因通用分割表现直接宣称品牌保真 |
| [Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2) | Grounding DINO 定位目标，再由 SAM 2 生成掩膜，示例输出 bbox 与分割结果 | 可验证“从另一张海报定位 Logo 再分割”；目标小或品牌抽象时不保证一次定位准确，不是即装即用 Logo 提取产品 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) / [输出说明](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html) | 文本检测多边形、识别内容和置信度 | 作为标题、正文的避让区域；OCR 不能覆盖所有非文字主体，需结合视觉分析 |
| [sharp](https://github.com/lovell/sharp) / [合成接口](https://sharp.pixelplumbing.com/api-composite/) | Node.js 确定位置的缩放、裁剪、透明合成 | 复用原 Logo 像素，避免图像模型重画；自身不决定审美位置 |
| [LaMa](https://github.com/advimman/lama) | 掩膜区域背景修复 | 仅在清除旧标识或局部内容后补背景时使用；不是文字排版引擎 |
| [ComfyUI](https://github.com/Comfy-Org/ComfyUI) / [服务端接口](https://docs.comfy.org/development/comfyui-server/comms_routes) | 节点工作流、队列、历史与 API | 可参考其可重放工作流，或作为内部独立 Worker；不应把整套 UI、节点依赖塞进现有 bf-api |

[IOPaint](https://github.com/Sanster/IOPaint) 有成熟的掩膜编辑交互可参考，但仓库已于 2025-08-13 归档，不作为新增生产底座首选。
rembg 的 MIT 代码许可与模型权重许可不同；其文档明确指出默认 BRIA-RMBG 权重的商业使用需要另外的协议。接入时固定并核验选定权重，不把“开源代码”理解成所有权重都可直接商用。

## 与现有源码核对

1. `PreservedAssetWorkflow.plan` 从发送给 Provider 的 references 中移除 preserve_assets 的原素材。Logo 不到 Seedream 在该路径是有意设计：手机保留原图形，最后本机合成；不能与人物素材意外丢失混为一谈。
2. `BrandPlacementPlanner` 用短边比例和方位计算落位，不读取 OCR 标题/正文区域。服务端给任意空白 box，旧包仍可能重新吸附到角落。
3. `PreservedAssetWorkflow.compose` 在 preserve_outside=true 时恢复原海报，仅在最终 box 内采用处理结果。服务端如果已经调整了外侧标题，手机会把这些调整盖回原图。
4. 本机 BrandAssetCutout 的复杂背景路径使用全部前景实例；没有“源海报内 Logo 区域”输入，不能等同于专用 Logo 提取。
5. ImageToolArguments 对部分原样 Logo 指令强制 both 或两个已检索历史图片引用，并要求 preserve_assets。两张上传图却需要 attached+source_indexes，两种契约仍有冲突。不能靠删除 preserve_assets 硬切服务端成品，否则旧包先在本地拒绝。
6. 普通多图生成/编辑已经支持 source_indexes，但发送原图仍由客户端完成。服务端可以在工具回程核验角色、编号、数量，不能从一张已提交图片恢复另外几张从未提交的原图。

## 推荐工作流

素材解析与角色绑定 → 获取原素材 → Logo 区域定位 → 去底及边缘处理 → 海报文字/主体区域分析 → 候选位置评分 → 必要时局部让位 → 原像素合成 → 遮挡/比例/完整性检查 → 现有产物返回接口。

位置选择规则由我们的任务服务负责，而不是假设某个开源库已经提供专业排版：
- 先满足用户指定方位，在附近空白区选位；不自动搬到完全相反的位置。
- 排除标题、电话、正文、二维码、人物脸部及关键产品区域，保留安全边距与品牌留白。
- 能直接放下时保持原海报像素；只有用户允许微调且没有合理空位时，才局部调整。
- Logo 的几何、文字和配色来自原素材，不让 Seedream 临摹；Seedream 负责需要生成的视觉内容。
- 去底不得误删 Logo 本身的白色部分、细线或封闭空洞；复杂背景结果必须检查，不承诺所有素材 100% 自动准确。

## 不出包的三条接入路径

### A. 复用现有手机原素材合成（优先验证）
服务端分析预览，选择旧包实际支持的落位；需要腾出区域时生成对应局部底图。
复用既有 preserve_outside 字段，只有用户允许局部调整时才允许采用调整后的整张底图。
关键是按真实本地落位算法检查遮挡，不能只检查 Agent 最初给的 box。
优点：原 Logo 保真路径已有，不增加新客户端协议。
限制：任意自由落位、复杂素材裁取、本机去底失败等仍受现有算法约束。

### B. 云端处理并返回最终成品（有条件接入）
现有 image_generate/image_edit 的可执行参数允许且不触发本地 preserve_assets 时，服务器可返回现有 url 格式的最终成品。
但强制本地原素材合成的请求不能假装通过新 flag 关闭：旧包不认识新 flag，还可能重复贴图或拒绝执行。
因此必须逐入口验收；不能将“新增一个图像 URL 接口”当作全部旧包兼容已完成。

### C. 服务端网页补充能力（兼容退路）
如果某入口被本地校验硬性锁住，可从聊天返回服务端处理页链接，在页面完成素材选择、Logo 裁取、去底与合成，提供最终图片下载。
无需安装新包，但会多一次页面跳转；自动回填到 App 图片库需要另验现有同步协议，不能预先宣称已支持。

## 服务部署边界

- bf-api 保留授权、账号隔离、工具规划和配置；bf-image 保留任务路由、幂等和账务。
- GPU 分割、较大 Python 模型放独立推理容器或现有可用服务，模型权重不打进当前 Node 云函数。
- sharp 等轻处理可置于独立媒体 Worker。云函数通过已有接口协调，客户端继续使用现有地址和返回结构。
- 为素材建立账号内 ID、角色、原始附件序号、发送槽位、哈希与用途，日志只记录这些必要信息，不记录完整图片或密钥。
- 外部品牌图标优先官方素材源，例如 [OpenAI 品牌资源](https://openai.com/brand/)，下载原文件而不是根据名称重新生成。下载、转存、使用规范及最后实际采用的素材版本都要记录。

## 上线前必须通过的验证

1. 已生成海报+透明 Logo：不压标题、不遮正文，图形比例正确。
2. 白底/彩底 Logo：输出透明背景，细线和白色图形不丢。
3. 来源海报含多个图标：提取用户指定 Logo，不把整张海报当前景。
4. 两张上传图（人物/底图）和三张参考图：实际 Provider 输入数量、顺序、角色正确。
5. 两张上传图（海报/Logo）：不触发旧包 both/attached 冲突；原素材合成执行一次。
6. 没有空白位置时，用户允许微调则小范围让位；要求完全不动原版式时不得擅自重绘。
7. 网络找品牌 Logo：采用官方正确文件，并真的进入合成，而不只是回复一个搜索链接。
8. 旧包端到端验证：实际返回工具参数能通过本地校验，手机不会把服务端调整恢复掉，也不再次贴 Logo。
9. 失败、超时、重复请求：已有产物和素材可复用，没有第二次隐藏扣费；不把基础图误报为成品。

本轮仅完成官方仓库调研和源码适配分析；未启用第三方图片传输、未安装模型、未部署额外推理服务。
