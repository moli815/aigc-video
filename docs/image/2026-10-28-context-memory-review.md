# 长期记忆与上下文审计（2026-10-28）

## 已核实的缺口
- MemoryService 原来只注入最近50条，旧记忆即便仍在库里也不会按问题召回。
- 对话只传最近40条，摘要每条仅取200字，摘要不足以作为细节数据库。
- 记忆更新没有刷新 updatedAt，跨设备同步可能认为它没有更新。

## 本轮落地
独立 ContextRecall → 查询相关长期记忆 + 早期/跨会话用户原文 → 有来源和时间的有限预算片段 → 原有 buildAPIMessages。
用户原文分块检索，末尾细节不因200字摘要截断丢失；不按日期淘汰旧记录。查询限定当前账号、排除会话和记忆墓碑。仅用户发言参与历史召回，不将AI推断写成用户事实。当前用户更正优先。
记忆更新刷新同步时间，异步提取增加会话凭证校验。保持 SwiftData/现有同步和 Provider 边界，不新增外部服务或永久密钥。

## 参考与选择
- https://github.com/mem0ai/mem0 ：按用户检索、更新与删除的记忆生命周期。
- https://github.com/langchain-ai/langmem ：事实/经历/行为分层，相关性与时间共同参与召回。
- https://github.com/muratcankoylan/Agent-Skills-for-Context-Engineering ：memory-systems 与 context-compression 分工，摘要保留决策/未决事项，不能替代原文检索。
本轮参考设计，没有复制第三方代码或安装技能；安装在开发工具上的 skill 不会自动成为 App 的运行时能力。

## 验收与边界
统一工具注册表加入 recall_history：前置模型可以将隐含描述改写成最多3组实体/同义关键词，按需重查旧记录，工具结果有来源且受10000字符上限约束。通过既有工具权限和执行管道，不增加第三方服务。这是Agent改写检索词，不是向量语义召回。
回归覆盖：超过50条后召回旧事实、中英关键词、无关信息、重复/预算、来源与更正规则、跨会话/账号隔离/删除、长消息末尾细节、记忆墓碑。
这是中文双字组/英文词的词汇检索基线，不是向量语义检索，不承诺纯同义改写、多跳关联或任意隐含指代100%找回。当前查询必须提供可匹配的线索。仅检索已经同步到本机的记录。
大历史量仍需持久索引，当前按页扫描文字，不读取历史图片。后续通过同一 Record/预算契约接服务端混合检索（实体/关键词+向量、重排），需先用固定语义用例验证，再部署；不得用额外提示词冒充语义召回已经实现。
删除会话与删除长期记忆是独立操作：只删除记忆不等于删除原始聊天记录。若需要全局遗忘，必须同时定义原文/摘要/索引清除策略，不能声称单个墓碑已经完成全局遗忘。
