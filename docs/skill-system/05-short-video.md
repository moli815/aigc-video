# 短视频脚本 Skill（short_video）

> 落地位置：`BossAI/Models/Expert.swift`（专家本体）· `BossAI/ExpertCore/Resources/ExpertSkills.json`（能力档案）
> · `cloudfunctions/bf-api/experts.json`（云端种子，`EXPERTS_SEED_VERSION = 3`）
> 契约测试：`Tests/BossAIiOSTests/ShortVideoSkillTests.swift`、`bf-backend/tests/expert-seed-contract.test.js`

## 1. 职责边界（最重要的一条）

| 请求 | 该谁接 | 不该发生 |
|---|---|---|
| 单条视频的选题、钩子、分镜、逐字稿、字幕、发布配套 | **short_video** | — |
| 长期 IP 定位、内容支柱、90 天规划 | `boss_ip` | 短视频不要越界给"IP 战略" |
| 流量获取、获客漏斗、投放 ROI | `traffic` | 不要凭感觉算投放回报 |
| 多渠道营销全案、内容日历 | `marketing` | 不要把"一周发什么"当单条脚本 |
| 20 分钟以上演讲/培训逐字稿 | `speech` | 不要用短视频结构硬套长讲稿 |

越界时的正确做法：**说明该由谁接，再交付自己能给的那部分**，不硬答。

## 2. 输入契约

- 必填：`topic`（主题/核心观点）。
- 可选：平台、受众、时长、表现形式、目标、风格、品牌背景、现有素材、账号数据、禁止项。
- 默认值（缺项时必须**明示**在用默认值，不要偷偷假设）：时长 30~45 秒；手机真人口播 + 简单字幕；不硬广；不编造数据。
- 用户说"直接出稿"时不要反复确认；只在"缺了会实质影响结果"时问**一个**问题。
- 没有账号数据就不谈"你的粉丝画像/历史完播率"——那是编造。

## 3. 工作流（8 步，已写进 prompt）

1. 解析主题/平台/受众/时长/形式/目标/禁止项，缺项用明示默认值补齐。
2. 给 **3 个实质不同**的创作角度（不是同义改写），各说明适合谁。
3. 给 **3 个不同机制**的开头钩子：痛点 / 反差 / 具体场景 / 结果先行，选三种。
4. 输出完整时间线脚本：时间段 / 口播 / 画面 / 屏幕字幕 / 剪辑提示；一个视频只讲一个观点。
5. 用 `speech_duration` 估算口播时长（计入停顿与字幕阅读），超时先压缩。
6. 政策、价格、统计数字、平台规则按需联网核实，标来源与日期；用户说不要联网就不搜。
7. 自检：前 3 秒具体性、信息密度、口语度、手机可拍性、禁止项、唯一 CTA。
8. 不合格最多定向修订一次；仍不达标如实说明缺口。

## 4. 输出结构

| 段落 | 内容 |
|---|---|
| 创作策略 | 一句话：目标受众 + 核心矛盾 + 切入角度 |
| 标题与钩子 | 3 个标题 + 2~3 个可替换开头 |
| 分镜脚本 | 表格：时间段 / 口播 / 画面 / 屏幕字幕 / 剪辑提示 |
| 发布配套 | 配文、封面文字、话题建议（按需） |
| 事实与质量自检 | 预计时长、待核实事实、是否含夸张承诺、是否守住用户约束 |

## 5. 标准样例（可直接作为回归基线）

**输入**：帮我写一条 30 秒短视频，主题是"为什么企业买了 AI 工具，员工还是没提效"，给企业老板看，真人口播，不要硬广，不要编造数据。

**创作策略**：用"买了工具但流程没变"的反差切入，给一个可落地的方法；不引用未经核实的行业数字。

| 时间 | 口播 | 画面建议 | 屏幕字幕 |
|---|---|---|---|
| 0–3s | 企业买了 AI，为什么员工反而更忙？ | 真人正面口播，直接进问题 | 买了 AI，为什么更忙？ |
| 3–9s | 很多团队只是把 AI 当搜索框，用完以后，复制、整理、检查还是靠人工。 | 电脑工作画面 → 切回人物 | 只买工具，不改流程 |
| 9–18s | 真正值得优化的，是把重复工作拆成固定步骤：输入、处理、检查、交付。 | 四步流程依次出现 | 输入 → 处理 → 检查 → 交付 |
| 18–26s | 先挑一个每周都会发生的任务，跑通流程、检查结果，再考虑推广给更多人。 | 人物口播 + 简单工作流示意 | 从一个高频任务开始 |
| 26–30s | 你们团队最想先自动化哪件事？ | 回到人物正面，留自然停顿 | 留言说说你的场景 |

**标题备选**：① 企业买了 AI，为什么员工还是没提效？ ② AI 工具买回来了，先别急着全员推广。 ③ AI 落地真正难的，可能不是工具。

**自检**：目标 30 秒需实际试读复核；无未经核实的行业数字；无硬性销售话术；手机+真人口播+字幕即可拍；只有一个 CTA。
**不承诺**播放量、涨粉或转化。

## 6. 编辑评分（只用于内部比较，不是爆款预测）

每项 0–2 分，共 12 分：开头具体性 / 受众明确度 / 核心观点单一性 / 信息可执行性 / 口播与画面可拍性 / 事实与约束遵守。
低于 9 分或触碰事实/授权/品牌红线 → 定向修订一次。
**该分数不得展示为平台算法预测或爆款概率。**

## 7. 能力边界（写进 `boundaries`，不靠模型自觉）

- 只交付可拍摄的脚本与方法，不保证播放量、涨粉、转化。
- 当前**没有**视频下载、ASR 转写、抽帧、剪辑渲染链路：用户给视频链接时，要求提供字幕或文字稿，不得声称"已逐帧分析"。
- 用户数据 / 计算结果 / 假设 / 联网事实必须分开标识。
