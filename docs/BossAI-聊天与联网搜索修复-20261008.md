# BossAI 聊天与联网搜索修复（2026-10-08）

## 截图所示问题

IMG_0257 中“2026 家庭 SUV 怎么选”位于本轮联网检索的候选来源表，不是旧会话消息，也不是内置汽车专项数据。用户输入的“主题：手机配置”缺少具体品牌、型号和版本，旧版把整段任务说明当成搜索词；多引擎搜索结果只排序而不排除零相关页面，导致汽车、作品、数据库等页面混入来源表。模型最终判断这六条都不能核实手机配置，但用户仍需读一大段无关说明。

先前那张 Windows 终端截图属于 CloudBase `tcb lowcode watch`，`<<<<<<<` 是待解决的代码合并冲突标记，与 BossAI 本轮检索无关。

## 修改

| 文件 | 修改 |
|---|---|
| `BossAI/ExpertCore/ResearchCore.swift` | 从“主题：…”模板提取真正的搜索主题；对缺少具体产品/版本的逐项配置核实请求给出澄清条件；不再把“手机”排除于相关性词之外。 |
| `BossAI/Services/WebSearchService.swift` | 排序前剔除标题和摘要与主题零匹配的搜索候选，避免无关页面进入来源表与模型证据。 |
| `BossAI/ViewModels/ChatViewModel.swift` | 对无具体对象的配置请求先提示补充型号，不发网络或模型请求；有具体对象时只用主题做预检索。 |
| `BossAI/Config/AppConfig.swift` | 模型内置搜索优先设置默认开启，并使用新设置键覆盖旧版默认关闭状态。 |
| `BossAI/Services/ProviderProfiles.swift` | 自定义模型未验证内置搜索能力时使用 App 搜索。 |
| `BossAI/Services/ChatService.swift` | 单个请求只挂载一种搜索后端；已知支持内置搜索的模型先走内置，服务端以 400/422 拒绝时重试 App 搜索工具。 |
| `BossAI/Views/SetupView.swift` | 说明搜索优先级和回退条件。 |
| `Tests/BossAIExpertCoreTests/ResearchCoreTests.swift`、`Tests/BossAIiOSTests/ResearchPipelineTests.swift` | 增加主题提取、缺目标澄清、汽车结果污染、内置搜索优先与失败回退的回归测试。 |

当前 DeepSeek Chat Completions 配置没有声明可用的服务端搜索能力，所以仍通过 App 搜索；将来切换到已验证支持服务端搜索的模型时才走内置。模型返回的联网答案没有可核对链接时，App 会补查一次。搜索结果过滤只能减少不相关候选，不能证明页面事实、发布时间或价格正确。

## 旧会话与记忆

正式运行的会话保存在本机 SwiftData；测试夹具在专用启动参数下使用内存数据库。源码没有预置汽车对话。长期记忆会跨会话注入提示词，但 IMG_0257 中汽车内容明确处于本轮候选来源表，因此本截图的根因是检索污染，不能据此判断旧数据恢复。备份导入是单独流程。

## 验证与复测

- GitHub Actions：`Expert correctness and performance` 跑 macOS Swift 核心测试与 iPad 模拟器集成/性能夹具；`Build Unsigned IPA` 生成可供侧载签名的未签名 IPA。
- 模拟响应测试覆盖搜索路由，不等于真实服务商联网质量测试，也不等于用户设备上的 Instruments 性能数据。
- 在新版中先发“请核实以下最新信息。主题：手机配置…”，预期先得到要求具体型号的简短追问，且没有无关来源表。
- 再发“核实 iPhone 18 Pro 的屏幕、电池和售价，优先官方资料”，预期只展示与该机型有关的候选来源；每项结论应能打开相应来源，不可验证的字段明确写未核实。
- 切换一个已验证支持服务端搜索的模型，检查优先走内置；切回 DeepSeek，检查走 App 搜索。真实结果、首字等待、总耗时和来源准确率仍需在设备上回填。
