# 决策记录：初始密码「可回查」为业务必需（风险接受）

- 日期：2026-10-24
- 决策人：项目负责人（用户）
- 背景：联合审计 §P1-10 建议改为「创建/重置时只显示一次，之后只能重置、不再保留可逆密文」。
- 决策：**不采纳**。初始密码必须能让管理员随时回查（客户忘记密码、客服补发、员工交接都依赖它）。
- 影响范围：`bf_deliveries.passwordCipher`、`bf_staff.passwordCipher` 继续保留；`GET /api/admin/deliveries`
  与 `GET /api/admin/staff/:id/password` 继续返回明文密码。

## 1. 已接受的残余风险

| 风险 | 说明 |
|---|---|
| 可逆存储 | 密码以 AES-256-GCM 加密存放在 `passwordCipher`，持有密钥者可批量还原历史密码 |
| 密钥与密文同边界 | 若未配置 `AES_KEY` 环境变量，密钥由服务自动生成并存在 **同一个数据库** 的 `bf_config/secrets`——能读库的人也能解密 |
| 管理员权限集中 | 管理员可查看任意员工密码与全部发放存档；一旦管理员账号失陷，等价于拿到了这批初始密码 |
| 批量暴露面 | 发放存档一次列表最多返回 200 条明文密码 |

## 2. 已实施的缓解措施（都在当前版本里）

1. **操作审计**：`bf_audit_logs` 记录 `deliveries.list.reveal` / `deliveries.list.masked` /
   `staff.password.view` / `staff.password.reset` / `staff.create` / `staff.disable`，
   含操作人、角色、目标对象、条数、`requestId`。审计体**不含密码**（有测试 `AUDIT-01` 反向断言）。
2. **最小权限**：员工只能看自己名下的发放存档（按 `staffId` 过滤）；查看/重置员工密码、停用员工仅管理员；
   管理员账号自身不能被重置或停用。
3. **止损开关**：`REVEAL_DELIVERY_PASSWORD`（管理台 → 系统设置 → 安全与限额）。
   默认 `1`（可回查）；**应急时置 `0`** 后列表立即只回 `passwordMasked:true`，不再解密，30 秒内全实例生效。
4. **传输与落库**：只在 HTTPS 接口返回，不写日志、不写前端存储；密码哈希用于登录校验，密文只用于回显。

## 3. 若发生泄露的应急处置

按顺序执行，**不要跳步**：

1. 置 `REVEAL_DELIVERY_PASSWORD=0`（止血：列表不再吐明文）。
2. 停用受影响的管理员/员工账号（`POST /api/admin/staff/:id/disable`，会留审计）。
3. 查 `bf_audit_logs` 里 `staff.password.view` / `deliveries.list.reveal` 的时间线，圈定暴露范围。
4. **轮换密钥**（会作废旧密文，属于破坏性操作，需先确认全量重置路径可用）：
   - `AES_KEY` 轮换后，历史 `passwordCipher` 全部无法解密 → 必须为相关账号走一次"重置密码"；
   - `TOKEN_SECRET` 轮换会让所有已登录设备重新登录（会员端与员工端都会）。
5. 通知受影响客户重置密码，并在发布记录里写清时间、范围、处置人。

## 4. 若要降低"密钥与密文同边界"的风险（可选，不影响可回查）

把**现有的** `AES_KEY` / `TOKEN_SECRET` 原样复制到 `bf-api` 的函数环境变量（注意：是**复制，不是轮换**）：

1. 从 `bf_config/secrets` 读出当前值（只读一次，不要粘贴到代码库、工单、聊天记录）；
2. 在函数配置里新增 `AES_KEY`、`TOKEN_SECRET` 两个环境变量，值完全相同；
3. 重新部署/等待实例回收，让新实例从环境变量读取；
4. 验证：老账号能正常登录、能正常查看历史发放密码（说明密钥一致）；
5. 确认无误后，再评估是否从 DB 文档中删除该副本。

> 未做这一步的原因：环境变量值必须经过人工搬运，属于**密钥操作**，且一旦传错就会让历史密码全部不可解。
> 需要做的时候按上面 5 步一次完成，不要中途改值。

## 5. 复核

- 每次管理员账号增删、每季度安全复核时检查 `bf_audit_logs` 的异常访问模式（同一账号短时间大量 `password.view`）。
- 若将来产品允许"创建即发一次性密码、不再回查"，本决策作废，按审计原建议迁移（先停写密文，再清历史）。
