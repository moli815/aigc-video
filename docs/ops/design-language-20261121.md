# 设计语言调优：从「俗」到「素」再到「有设计感」（2026-11-21）

## 一、问题演进

| 版本 | 时间 | 做法 | 结果 | 问题 |
|---|---|---|---|---|
| 第 1 版 | 03:59 | 模型自由发挥 | **俗** | 深蓝金光晕、logo 白底、文字重叠、横版 |
| 第 2 版 | 04:17 | 加禁令：不要光斑、不要装饰、留白≥1/3、≤3 色系 | **素** | 只说了「不要什么」，模型最安全的选择就是少放东西 |
| 第 3 版 | 05:10 | 结构优先 + 密度目标 + 美学手法可选 | **有设计感** | — |

## 二、核心判断：装饰 ≠ 结构

- **装饰**（会显俗）：漂浮光斑、随机插画、多余镜头光晕、粒子、水印
- **结构**（设计感来源）：网格、分区、编号、字体层级、色块、细线、出血裁切

第 2 版把两者一起禁掉了，所以变素。第 3 版只禁装饰，同时给出结构手法作为**可选项**。

## 三、调研依据

| 来源 | 结论 | 影响 |
|---|---|---|
| Lovart《AI 海报 prompt 五层框架》 | 「信息密度由渠道决定：小红书/朋友圈要高密度；电梯海报要低」；「不说层级，AI 会把信息平等塞进画面，出来是一锅粥」 | 加渠道判断 + 信息层级 |
| Reddit r/PromptEngineering | 「模型用统计上最常见的选择填补你没说死的地方」 | 不能只给禁令，要给正向结构方向 |
| GPT Image 2.5 真实 prompt 样本（5 个） | 网格坐标（A–F/1–4）、编号索引、micro-labels、字体悬殊层级、risograph 材质 | 提炼成「美学参照」六条可选手法 |

## 四、改动（4 处）

### 1. `intent-contract.js`：把「禁令优先于形容」换成「结构优先于装饰」

```
【结构优先于装饰】信息密度按投放渠道定：门店玻璃贴、社群、朋友圈这类近距离快刷场景，密度要高
——用户给到的信息尽量都排进去，不要大片留白；层次靠结构（网格、分区、编号、字体层级、色块、细线）
而不是靠装饰（漂浮光斑、随机插画、多余光晕）。用哪几种、怎么组合，由你判断，不要套固定模板。
```

### 2. `intent-contract.js`：新增「美学参照」（六条，明确非强制）

```
【美学参照】需要更强设计感时，可从这些手法里挑（不是必须，也可以自创）：
用网格组织版面；字体层级拉开悬殊对比——超大标题配极小注释；用编号或索引标记信息；
用细线或色块切分区块；挑一个信息点放大成视觉主体；图片出血或裁切增强张力。
只挑用得上的，不要全堆上。
```

### 3. `prompt-contract.js`：去掉会把画面做空的约束

| 第 2 版 | 第 3 版 |
|---|---|
| 背景只用一种处理方式 | 用结构建立层次 |
| 全图不超过 3 个色系 | （删除，色数由模型按行业判断） |
| 四周留白不少于三分之一 | 信息密度按用途判断，**不要为了留白把内容抽空** |

### 4. `tool-tag-parser.js`：修复边界检测回归

第 2 版上线后，安防组又出现标签泄漏。原因：

```js
// 旧：在 SSE 整行上永远匹配不到行尾
if (/<[a-z_]*$/i.test(s)) return true;
// 新：检测 JSON 引号前的半截标签，并还原 \u003c 转义
if (/<[a-z_]{0,12}"/i.test(s)) return true;
```

7/7 用例通过。复测 `文本 0 字 / toolArgs 1998`，不再走本地兜底。

## 六、反直觉的发现

**提示词从 720 字缩到 372 字，画面反而更有设计感。**

因为不再逐条规定版式，Seedream 才有空间按自己的美学判断组织版面。这与「不能写死」的判断一致。
