## 候选实现

- bf-api/intent-contract.js 只为新建商业海报整理已确认信息。去掉该路径的行长、栏目数和默认锁定 3:4 的叠加规则。保持用户给的视觉风格、少字和极简，型号、价格、日期、电话使用已确认信息。大纲、摘要和历史偏好不能替代本轮显式要求。
- shared/poster-delivery.js 负责该路径的文案规范和唯一 5.5 提示词编译，兼容旧生产接到的数组、字符串、分组字典及顶层产品字段。单独标记印刷文字并加双引号。让主视觉、实拍细节、图标和关系图服务对应业务信息，视觉描述保留内容锚点，背景的场景、材质和光影不统一套模板。
- bf-api/index.js 将标签补发接到原统一工具回程，在调用成功后补一个 SSE 结束帧。正常工具帧已经交付时忽略文本里重复的标签。
- bf-image/index.js 候选对命中路径使用新编译器，其余路径沿用既有编译。回退追加文案只在供应商直接出成稿时允许，合成底图、overlay、改比例、拆层和局部像素编辑各自保持文案控制。响应、新旧 App 字段、状态码、鉴权、会话、会员余额、依赖和平台凭据均不修改。

## 查过的资料和取舍

- 火山 [Seedream 5.5 能力说明](https://docs.volcengine.com/docs/ark/seedream-5-5?lang=zh)、[出图 API 参数](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)、[提示词指南](https://docs.volcengine.com/docs/ark/image-generation-tutorial?lang=zh)。采用应用用途、简洁视觉描述、文字引号与宽高像素参数。300 字是提示词建议，不能据此截断客户给定的 500 字；候选 559 字原文保留。拆层是单图处理，需要把底图和其他图层与补字重新合成；文字识别和样式描述受文字类型与识别置信度限制，不能承诺原生海报每个字都正确。
- [Polotno Schema](https://polotno.com/docs/schema) 与 [Canva Autofill](https://www.canva.dev/docs/apps/rest-apis/autofill-guide/) 展示独立的文字与图片对象和可替换字段。借鉴把已确认文案单独保存并按设计放置的契约。前者核心 SDK 商业授权，后者 API/OAuth 有访问要求，本轮不导入或调用。
- [poster-generator-skill](https://github.com/howardz27/poster-generator-skill) 的 MIT 版本固定于 fa2a40bf0943c14dbcf2dfd86a2efe66fa8b4cbc，借鉴布局、风格和验收分开；它生成提示词，公开示例不能证明中文长段落正确。图层方案参考 [此前的运行时与许可调研](design-composition-research-20261104.md)，优先复用当前 Node18 包里的渲染器和字体，不引入外部训练模型或新浏览器运行时。

## 已验证

同一份 559 字资料做了历史 ZIP 的本机回档对照。11/18 包的排字服务向 5.5 请求 3240×1296 的无字素材，印刷文案由合成器处理。11/23 包仍选择同一无字素材，但又执行临时兜底，把其中 7 项完整文字以及其他简写塞回请求，导致底图同时收到禁字和印字指令。进一步核对旧修字记录，重放因 NATIVE_TEXT_EXTRA_COPY 被拒。候选将这两类路线分离，直接成稿向 5.5 传 17 项原文，程序排字仍取 3240×1296 的素材底图，显式 overlay 也无文案泄漏。画布数值指供应商素材请求，成品是另一画布。


以线上只读备份为基线构建本机候选。ZIP 差异白名单只命中 API 的 4 个文件和图片服务的 2 个文件，无缺少模块、无依赖变化。线上最后修改时间分别是 API 11/23 10:25:45、图片 10:26:02、账务 11/18 11:10:44，三者为 Active、InstallDependency FALSE。

本机 Node18 使用真实候选 ZIP、旧工具 schema 与隔离会员夹具。JSON 分组字典、标准分片 SSE、标签 SSE、标签与工具帧混出均把同一份 17 项文案回传一次；明确极简用例仅 1 项。两个工具结果接入 /image，供应商夹具捕获模型 doubao-seedream-5-5-261028、画布 1776×2368。密集用例 559 字、供应商提示词 972 字，每条原文出现一次；极简用例 10 字、提示词 223 字，未加密集指令。夹具提供合成位图来验证尺寸，不能作为样张。真实模型调用、客户账单变化、生产写入均为 0。

本机保存在 outputs/generation-pipeline-review-20261123。before.json 与 before-*.zip 是回滚基准。gate-*.json 是产物文件差异表示。http-report.json、dense-provider-request.json、sparse-provider-request.json 是本机验证，verify-http.cjs、verify-baselines.cjs、verify-composition.cjs、verify-background.cjs 与 size-fixture.cjs 可复跑；现有夹具依赖本机字体和样张。existing-visual-comparison.jpg 是历史样张缩略对照。

## 下一轮接手与发布

1. 先检查是否有其他会话在工作、Git 和当前线上版本。将最新线上 ZIP 与 before.json 比较，有更新就重新备份并基于新版重做白名单候选。上一版只能作为视觉与模块实现参考，不整包回档。
2. 使用同一批非客户素材在隔离环境跑三个用例，保留实际模型输入、素材角色、最终图和费用。首轮各一张，优先验证模糊续写的 550 字以上、带真实素材与图解的商业海报；随后做极简明确风格及横竖重排兼实物保真。复用已有图做失败分析，仅在具体代码或配置改动后再付费重跑该用例。
3. 逐项核对完整文案与事实，逐字检查细笔画、字距和标点，按成品实际尺寸看背景、阅读顺序及留白，放大看素材轮廓和边缘。若出图文案准确则保留原版风格；局部字形失败时用现有拆层/清底/定位/字形替换实验，只处理能对准且清干净的文字层。识别不稳定时先验证字号、画布、位置和字体，不用通篇模板叠字掩盖。未经确认的日期、价格、Logo 或字形错误均算失败。
4. 得到可交付样张后才准备生产切换。先通过新版标记和兼容兜底检查部署顺序，并做一次预发布制品安装检查；依当时线上版本补备份，使用官方 SCF 上传完整固定依赖包且 InstallDependency FALSE，下载逐文件核验；健康、旧合同、本地签名资产、额度状态与幂等出现变化即恢复本次备份，旧包也重新核验。当前生产没有切换，无需线上回滚。
