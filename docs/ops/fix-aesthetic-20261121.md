# 工具调用格式归一化 + 比例修正 + 审美策略调整（2026-11-21）

## 一、先确认：提示词到底谁在润色

**结论：前置模型写 prompt，Seedream 5.5 再用内置 standard 优化器润一遍，两层都在跑。**

依据：

| 来源 | 原文/结论 |
|---|---|
| 火山方舟《图片生成教程》 | 「Seedream 5.5、Seedream 5.0 flash / lite、Seedream 4.5 **仅支持 standard 模式**」 |
| Mage 实测博客 | 「Seedream 5.5 has no Prompt Optimizer setting: **it always takes the standard pass**」 |
| 第三方 API 文档 | 「optimize_prompt_options.mode 传 fast 会返回 400，只能用默认的 standard」 |

代码侧现状：`doubao-seedream-5-5-261028` 的 `fastPromptMode:false`，且 `if (caps.fastPromptMode && !image)` 双重门槛。
这只意味着「不显式传参」，而 standard 是默认值，**所以润色一直在生效，我们也没法关掉它**。

因此「审美差」不是缺少润色，而是**我们给的 prompt 把版式写死了**。

## 二、修复 1：工具调用四种格式归一化（bf-api）

### 问题

模型会随机输出四种形态，线上只认第一种：

```
① 标准 tool_calls（delta.tool_calls）
② <｜DSML｜ calls><｜DSML｜ invoke name="image_generate"><｜DSML｜ parameter ...>
③ <tool_call>{"name":"image_generate","arguments":{...}}</tool_call>
④ 混合体：<tool_call>{...} 但结尾是 </｜DSML｜ parameter>
```

2/3/4 会以文本形式直接推给客户端，用户看到一屏乱码且出不了图。2026-11-21 的 4 组多场景测试**全部命中**。

### 改动

新增 `cloudfunctions/bf-api/tool-tag-parser.js`：

- `parseTaggedToolCall(text)`：DSML 与 `<tool_call>` 两种格式都归一成 `{name, arguments}`
- `repairJson()`：修复 JSON 字符串里的裸换行（模型常把 prompt 直接换行写进 JSON，导致 `JSON.parse` 失败）
- `flattenText()`：把对象/数组型 `structured`（如 `{headline, product_items[]}`）扁平化成文本
- `stripToolTags()`：解析失败时剥掉标签，降级成纯文本
- `looksLikeToolTag()`：判断是否出现标签迹象（含全角竖线「｜」，以及以 `<` 结尾的跨块边界）

`index.js` 两处接入：

1. **流式**：转发前检测标签迹象 → 转入缓冲不发给客户端 → 流结束后解析成标准 `tool_calls` 帧补发；失败则剥标签降级成文本
2. **非流式**：`message.content` 含标签时同样归一化，``content` 清空、`finish_reason` 改 `tool_calls``

日志标记：`tool_tag_buffered` / `tool_tag_converted` / `tool_tag_unparsed`。

### 实测

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 正文泄漏字符（烘焙组） | 1367 字标签文本 | **0 字** |
| tool_args | 0 | 1327 字节 |
| 本地解析是否被触发 | 是（脚本兜底） | **否**（服务端已修好） |

## 三、修复 2：比例被文本里的方向词带偏（bf-image）

### 三层坑

`shared/poster-reformat.js` 的 `ratioOf()` 原来用「文本里最后一个方向词」判断横竖：

| 场景 | 提示词片段 | 误判结果 |
|---|---|---|
| 否定表达 | 「画布比例严格 3:4，**不要横版**」 | 判成横版 → 3:4 被过滤 → 兜底 **16:9** |
| UI 元素 | 「一条**横向**的服务保障条」 | 同上，2:3 被判不合法 |
| 物料名词 | 「促销**横幅**海报」 | 「横幅」被当成版式方向 |

### 改动

1. **客户端已给比例时直接采信**：`aspect_ratio` 合法（宽高比 0.25–4）就返回它，不再用文本校验方向
2. **方向词剔除「横幅/竖幅」**：中文里这两个词常指物料而非版式
3. **保留否定归一化**：`normalizeDirection()` 把「不要横版」翻成「竖版」，反之亦然，仅在客户端没给比例时兜底

### 实测

| 用例 | 修复前 | 修复后 |
|---|---|---|
| 烘焙组真实提示词 | 16:9 | 2:3 |
| 安防组真实提示词 | 16:9 | 2:3 |
| 码趣 / 齿悦 | 正确 | 正确 |
| 边界 5 例（否定/横幅/UI 元素/空值） | — | 5/5 |

线上实测：安防组从 **2816×1584（16:9，文字重叠）** 变为 **1776×2368（3:4，版式清晰）**。

## 四、修复 3：把版式交还给 Seedream（审美）

### 根因

`requirement-guard.buildRequirements` 用「1. 2. 3. …10.」编号清单给模型下要求。
**模型会模仿输入格式**，于是把 prompt 也写成 10 条编号版式（「1. 顶部左侧… 10. 右下角预留」）。
Seedream 收到一份坐标说明书，只能照着摆，画面死板、背景堆装饰。

### 依据

| 来源 | 结论 |
|---|---|
| 官方提示词指南 | 「结构比形容词重要，写位置和模块关系，少写高级感/氛围感」；建议 30–120 词，上限约 600 词 |
| Reddit r/PromptEngineering | 「模型会用统计上最常见的那个选择填补你没说死的地方——而那正是大家看腻的样子」 |
| 社区模板（小互等） | 「高级感不是被描述出来的，是被禁令保护出来的」；AI 会自行加光斑、光晕、飘叶、水印 |

### 改动

| 文件 | 改动 |
|---|---|
| `requirement-guard.js` | 交付要求改为段落式（分号连接），去掉编号，避免模型模仿 |
| `intent-contract.js` | 新增三条：**不要写版式清单**（不列坐标/像素/几列几行）；**禁令优先于形容词**（排除光斑、光晕、随机装饰、水印、跨页大字标语、多字体多颜色混排）；**风格按行业适配**（烘焙暖色食欲、医疗克制、教育明亮、安防冷静但避开深蓝金光晕模板） |
| `prompt-contract.js` | 末尾新增「画面纪律」：背景只用一种处理方式；不超过 3 个色系；留白不少于三分之一；无水印无随机标语 |

### 提示词前后对比

**修复前**（1020 字，编号清单）：

```
【版式结构，自上而下】
1. 顶部左侧：品牌 logo 直接使用附件原图形...
2. 品牌行下方一行小字...
3. 大标题（最大字号，深棕）。
...
10. 右下角预留一块干净的浅色空白方形区域...
```

**修复后**（720 字，关系式 + 禁令）：

```
竖版秋季新品海报（高明显大于宽），用于烘焙店贴在门店玻璃上。底图角色"门店实拍"是画面主视觉...
整体气质：干净、暖、留白充足、日式面包店的安静手作感，而不是电商促销页。背景以奶油白、麦麸米色、深棕木色三色为主，少量焦糖橙作价格与重点标记。标题用有手作感的衬线或宋体，正文用清晰的无衬线体，字体不超过两种...
禁止漂浮光斑、镜头光晕、随机装饰图形、水印、跨页大字标语、多字体多颜色混排、大红色打折风格、卡通插画。
```
