# 元素化改造：从「纯色 + 文字」到「每块都有图形」（2026-11-21）

## 一、判断修正

上一轮写「不要装饰」，模型理解成「少放东西」，做出纯色底 + 文字块。

参照 ChatGPT 的三张信息图，那些城市剪影、云平台节点图、行业场景缩略图**不是装饰，是内容本身的可视化**。

正确表述：**元素必须服务内容**——与主题无关的随机图形不要，与内容直接相关的元素必须有。

## 二、参考图提炼的八条手法

1. 顶部信息条：logo + 公司全称 + 电话（带电话图标）
2. 主标题超大（占上部 1/5），渐变或描边字
3. 色带 / 圆角卡片分区，不是留白分割
4. 每个功能点配一枚图标
5. 行业覆盖用实景缩略图（商业综合体/学校/医院/工厂…）
6. 系统关系用示意图（云平台中心 + 放射连线）
7. 背景有层次：城市剪影 + 光带 + 渐变，不是纯色
8. 信息密度极高，但每块都有图形配合

## 三、改动

| 文件 | 改动 |
|---|---|
| `intent-contract.js` | 【结构优先于装饰】→【元素必须服务内容】：背景要有层次（氛围底图/渐变光效/纹理/行业剪影至少一种）；每区配与主题直接相关的视觉元素；元素必须来自内容本身 |
| `intent-contract.js` | 【风格贴合场景】补元素类型：烘焙配产品特写与原料工艺插画；医疗配诊室实景与设备示意；教育配课堂场景与进阶路径；安防配城市剪影、设备特写、联动示意 |
| `prompt-contract.js` | 画面纪律改为三条：① 背景不要纯色；② 每个信息区块必须有图形，**整块只有文字视为不合格**；③ 不出现与主题无关的随机图形 |
| `requirement-guard.js` | 附件 ≥3 时追加：除指定的主视觉与旧稿外，其余图片仅作信息参考，**不要把整张界面截图贴进画面** |

## 七、经验

1. **禁令要区分对象**：禁装饰，不是禁元素。写「不要装饰」模型会把内容型图形一起砍掉。
2. **要有「不合格」判据**：只写「建议每区配图」模型会忽略；写「整块只有文字视为不合格」才会执行。
3. **行业锚点要给具体元素**：只说「暖色食欲感」没用，要说「产品特写 + 原料工艺插画」。
4. **模型会自己造出反向指令**：它写进 prompt 的「留白充足」「极少量点缀」会与我们追加的约束打架，所以追加的约束要用更强的判据（不合格 / 必须有）。
