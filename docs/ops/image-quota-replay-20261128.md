# 手机生图断线重取、组图预留与重复成图

## 复现与影响

| 优先级 | 用户操作及旧结果 | 源码原因 | 验收 |
| --- | --- | --- | --- |
| 高 | 有效会员完成最后一张图后断线，原请求重发得到「本月额度已用完」 | 单图入口先拦截余额，再查已经完成的任务 | 用原请求编号取到本人原文件，额外消费为零。用新编号仍返回额度用完 |
| 高 | 一组图片启动后重发启动请求也报额度用完。事务预留刚好占满额度时，执行第一张就失败 | 组图启动先判断能否再次消费。执行子图时又把本组预留算作其他任务已占用的钱 | 重发取得原任务。已预留的子图从父任务转入相应金额，账户总预留保持一致 |
| 高 | 海报首张已保存并记账，结构检查报缺标题时又出一张。首次响应显示第二张，重取时显示第一张 | 旧分支在结束记账后调用第二次生成，修改返回网址。第二次转录为空时还会被当作无缺项 | 模拟缺标题，同一轮只有一次生成、一次记账，首次与重取返回同一成品 |
| 中 | 普通无字插画也尝试调用视觉转录 | 结构提取器即使没找到待核对信息也返回一个对象，调用方将空对象视作有文字要查 | 缺少具体待核对文字或数字的插画，转录调用数为零。有主标题的海报仍会核对 |

## 手机到云端的处理

iOS 的 ImageUseCase 沿用请求编号，ImageService 随图片请求发送编号，并识别服务端的 IN_PROGRESS。此次修复在 bf-image 完成。有效会员余额耗尽时，单图入口按账号、请求编号和已绑定素材读取原记录。归档图片重新签发下载地址。已在执行的任务返回等待状态。读取旧任务不能创建任务、恢复付费执行或增加记账。会员停用、到期、额度服务异常继续按原错误处理。

组图启动时已有任务会返回同一个任务编号。使用事务预留的组图在执行子项时，额度检查只排除本组已核实归属的预留。真正执行前，原有事务负责把相应金额转给子项；其他任务的预留仍计入占用。用户明确要求补画失败子项时仍须通过付费检查。

文字复核继续记录有依据的标题、电话、产品或报价缺失。成品入库后的复核只写诊断。这项修复保证同一操作交付的文件一致，文字质量仍须在定稿前验收。

## 对照产品与复测

Stripe 将请求编号与已执行结果关联，AWS 也将重试是否代表同一用户意图作为接口设计的一部分。此处复用请求编号和结果重放的设计，并沿用本项目的会员及素材权限检查。运行时为现有 Node.js 云函数，未引入外部代码、依赖或许可证。 [Stripe 幂等请求](https://docs.stripe.com/api/idempotent_requests) · [AWS 重试设计](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

运行 `node --test tests-backend/quota-replay-http.test.js` 可复测七个普通请求场景，其中供应商用本地替身。修复前六个用例失败，一个会员拒绝用例通过。候选全套后端回归见 `outputs/replay-audit-20261128/full.tap`。生产对照使用隔离账号、已归档 PNG 和现有组图任务。上线前两个正式入口均返回 429，账号额度为零。该验证不重放客户原对话，不调用真实生图，不能据此归因客户截图中的每一次重复。
