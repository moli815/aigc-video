# 方案 B：原生整图 + 确定性文字校验 + 原位修复

> 2026-11-12 22:0x 起草。**仅方案，未改任何代码。**
> 所有能力、参数、价格均来自火山引擎官方文档与本机源码核对，不是推测。

---

## 0. 一句话结论

**能不能做到：能。而且最难的一块——"知道每块文字在画面的哪个像素位置"——官方已经给了参数，我们的代码里也已经写好了，只是从来没人调用。**

方案 B 的真正形态不是"让模型少写错字"，而是：

> 让模型画整张图（保留真实感），把文字层拆出来单独验，错的按原坐标原位换掉，验不过就不交付。

---

## 1. 先纠正三个误判（这是之前一直修不好的原因）

| 误判 | 事实 |
|---|---|
| 换个更强的模型就好了 | 换别家仍然有错字率，只是从"错得明显"变成"错得不明显"。风险没消失，只是藏起来了。 |
| 提示词写"中文必须正确"就好了 | 对字形没有约束力，只会让构图更拘谨。模型做的是像素重建，不是字形渲染——它学的是"这里有一块像字的纹理"，不是"这几个字的笔画"。 |
| 多生成几次总能碰到对的 | 治标。这次 7 张全废，账单 ¥4.62，问题一个没解决。 |

**根因是分工错了**：文字正确性可以逐字比对（确定性），画面美感只能人眼判断（主观）。把两件事塞进同一个环节，验收口径永远写不清。

## 2. 官方已有的两个能力（已核实，非推测）

### 2.1 图层拆分 `layer_decomposition`

官方参数原文：

```json
{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "<待拆分图片>",
  "layer_decomposition": true,
  "size": "2K"
}
```

返回：

- **1 张底图 + 最多 16 个独立图层**
- 每个图层是**带透明通道的 PNG**
- 每个图层带 `z_index`（叠放顺序）和 `bounding_box.absolute`（**在底图坐标系中的绝对像素位置**）
- 被主体遮挡的背景区域**会被自动补全还原**

官方示例就是"把海报拆成 7 个图层，包括 6 组文字"，并且支持用 `<bbox>180 64 812 198</bbox>` 这种归一化坐标**精准指定要拆哪一块**。

**这一条解决了什么**：以前不知道错字在哪、不敢动，动了就怕把整张图改坏。现在每块文字的精确像素框是官方返回的，不是猜的。

### 2.2 坐标定位编辑

```json
{ "prompt": "将 <bbox>120 180 640 760</bbox> 区域内的文字替换为 “全国合作伙伴招募中”，其余画面保持完全不变" }
```

- 归一化坐标 0–999，左上角 (0,0)，右下角 (999,999)
- 支持点选 `<point>`、框选 `<bbox>`、箭头、手绘标记
- 官方明确："只修改目标区域，其余画面保持像素级不变"

**这一条解决了什么**：改字只改那一块，不会引起整图漂移。

### 2.3 我们自己的代码现状

| 能力 | 状态 | 位置 |
|---|---|---|
| 拆层请求参数 | **已实现** | `bf-image/index.js:1486` `payload.layer_decomposition = true` |
| 模型能力表 | **已实现** | `MODEL_CAPS` 里 pro/flash 均 `layers: true` |
| 拆层分档计费 | **已实现** | `IMAGE_COST_PRO_LAYER_LARGE/SMALL` |
| 路由支持 decompose | **已实现** | `index.js:212` |
| 按官方坐标原位重建文字 | **已写但从未调用** | `native-layer-typography.js`（读 `bounding_box.absolute`、分配文案、真实字体渲染、避让装饰线） |
| 文字渲染器 | **已写但从未调用** | `surface-typography.js`（resvg + 真实字体 + 抗锯齿） |
| 文字校验 | **没有** | — |
| 接线 | **没有** | 上述两个模块被引用次数 = 0 |

**结论：管道铺好了，差最后三公里。**

## 3. 方案 B 的完整闭环（四层）

```
用户一句话
   ↓
[1] 模型原生整图（Seedream 5.0 Pro 2K）
   ↓  画面、光影、材质、构图全部由模型决定，保留真实感
[2] 图层拆分 layer_decomposition=true + bbox 指定文字区
   ↓  得到：底图 + 每块文字的透明 PNG + 绝对像素坐标
[3] 逐块校验（本地离线 OCR，零 API 成本）
   ↓  读字 → 与定稿文案逐字比对 → 出「通过 / 错在第几块第几个字」
[4a] 全对 → 进美观检查 → 交付
[4b] 有错 → 按该块 bbox 坐标重绘（只改这一块）
        ↓ 再错 → 真实字体原位重建（native-layer-typography）
        ↓ 再错 → 拒收，明确告知用户哪几个字没过，不静默交付
```

### 3.1 校验为什么必须用本地 OCR，而不是让模型自查

已有实测证据：让同一个视觉模型"检查错字并修正"，它把"全国全国"的重复消掉了，**同时把电话 400 改成了 00**。同模型自查不能当验收。

本地 OCR 的价值：

- **确定性**：输出是字符串，比对是 `===`，不是"模型觉得没问题"
- **零成本**：`rapidocr-node`（npm，Apache-2.0，ONNX Runtime，PP-OCRv5/v6 中文模型），本地跑，不上传图片，不花一分钱
- **不需要云权限**：绕开腾讯云 OCR 的 IAM 问题，你之前拒绝的那条路不用走
- **读的是文字层不是整张海报**：单块小图、背景已去掉，准确率远高于读整图
- 返回逐字坐标和置信度，能定位到"第 3 个字错"

⚠️ 限制：`rapidocr-node` 要求 Node 24+。当前函数跑在 Node 18/22，需要单独跑一个校验 sidecar，或者用 `onnxruntime-node` + PP-OCR 模型自己接（工作量更大）。这是唯一需要提前拍板的技术选型。

### 3.2 修复的三级回退

| 级别 | 手段 | 效果 | 成本 |
|---|---|---|---|
| L1 | 按 bbox 坐标重绘该块，文案加引号明确 | 字体风格自适应，最自然 | 0.60 元/次 |
| L2 | `native-layer-typography` 真实字体原位重建 | 文字 100% 正确，但字体可能与画面不完全一致 | 0 |
| L3 | 拒收 + 明确告知 | 不交付错图 | 0 |

**关键原则：绝不因为"大部分字对了"就放行。** 电话、价格、日期、公司名错一个字就是废图。

### 3.3 美观怎么保证（不能只靠"感觉"）

分两类指标，一类可以算，一类要评。

**可以算的（零成本，从图层坐标直接得）：**

| 指标 | 怎么算 | 门槛 |
|---|---|---|
| 对齐 | 同类元素左边缘 / 基线是否落在同一轴 | 偏差 ≤ 2px |
| 间距 | 元素间距的方差 | 方差 ≤ 阈值，无过密/过疏 |
| 层级 | 标题/副标题/正文/辅助的字号比 | 主次比 ≥ 1.5，层级不得倒挂 |
| 留白 | 主体包围盒占画面比例 | 15%–60%，不得拥挤 |
| 出血 | 元素距画布边缘 | ≥ 画布短边 3% |

这三个指标（alignment / spacing / hierarchy）来自 UMC-Design 的论文评测方法，美团 PosterReward 用的是同一套设计四原则（对比、重复、对齐、亲密性）。

**要评的（一次视觉调用）：**

按 PosterReward（CVPR 2026）的五维打分：

1. Foundational Visual Quality（基础画质）
2. AI Artifacts（AI 痕迹：伪字、塑料感、错位）
3. Textual Accuracy（文字准确性）
4. Prompt Fidelity（是否符合用户要求）
5. Aesthetic Value（审美）

**硬门槛：文字准确性必须 100%（由 OCR 判定，不由模型判定）；其余四项 < 4.0/5 不进交付。** 这一条把"模型说好"和"真的能用"分开。

## 4. 成本测算（官方价，已核实）

### 4.0 压成本版（用户要求单张 ≤1 元，本节为最终采用方案）

用户明确不接受 2.15 元/张。改为以下三招，闭环能力不减：

**招式一：1.5K 替代 2K。** 官方 1.5K 与 1K 同价、效果更优；2K（2048² ≈ 419 万像素）必然越过 261 万分界进高档 0.60，1.5K 稳定落在低档 0.30。手机端交付够用，用户明确要印刷时才升 2K。

**招式二：只拆关键文字块。** 一张商业海报报废只有两类原因：标题错、底部信息（电话/公司名/地址）错。因此只拆「底图 + 标题 + 底部信息」，2 个文字层，不是全拆 8 层。

**招式三：校验前置，先免费后付费。** 生成后先跑本地 OCR 整图粗筛（0 元）。全对直接交付，**不触发拆层**；出现可疑块才拆层定位。

| 情况 | 生成 | 拆层 | 重绘 | 合计 |
|---|---|---|---|---|
| 一次通过（OCR 粗筛全对） | 0.30 | 0 | 0 | **0.30 元** |
| 需修 1 块 | 0.30 | 0.15+2×0.15=0.45 | 0.30 | **1.05 元** |
| 需修 2 块 | 0.30 | 0.45 | 0.60 | **1.35 元** |

按 50% 一次通过率测算平均 ≈ **0.68 元/张**，与当前单张 0.60 基本持平；而当前平均一张 0.66 元且全部报废（7 张 ¥4.62）。

**粗筛的误判方向必须可控**：置信度低于阈值的字一律判「可疑」送拆层复核，宁可多花 0.45 元也不放行错图；绝不允许「低置信度判通过」。

### 4.1 全量拆层版（不采用，留档对比）

火山方舟官方定价：

| Seedream 5.0 Pro 单图 ≤261 万像素 | 0.30 元/张 |
| Seedream 5.0 Pro 单图 >261 万像素（2K） | 0.60 元/张 |
| **图层拆分 ≤261 万像素** | **0.15 元/层** |
| **图层拆分 >261 万像素** | **0.30 元/层** |

      + 6 块文字（小图）6×0.15   0.90
      + 2 装饰层 2×0.15          0.30
拆层输入图（原参考图）           0.02

## 6. 这套也救不了的情况（必须提前说）

1. **文字和画面深度融合**：发光字、透视字、手写体、刻在物体表面的字。拆层拆不干净，OCR 也读不准。
2. **拆层失败**：官方说最多 16 层，但复杂海报可能拆成一堆碎片，或把文字和装饰合并。需要失败检测 + 回退。
3. **用户要的就是"艺术字"**：书法、涂鸦、变形字。这种本来就不该逐字校验。
4. **旧 App 的本机 Logo 合成**：还在手机端，服务端改不了，只能等出包（B-17）。
5. **美观的最后一公里**：几何指标能挡住"歪、挤、乱"，挡不住"平庸"。真正的设计感还是要靠参考图和人工挑图。

## 7. 备选方案（如果 B 走不通）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A 留白叠字** | 模型只出无字底图，文字全部我们排 | 文字 100% 准 | 容易变成 PPT/资料页——这正是你现在最讨厌的 | 不推荐单独用 |
| **C 换模型** | Qwen-Image / GPT Image 2.5 | 中文文字能力确实更强 | 换一家仍有错字率；接口、计费、合规都要重做 | 可作为 B 的补充，不作替代 |
| **D 人工审核台** | 生成后进后台，人工挑图改字 | 质量最可控 | 人力成本高，无法规模化 | 可作为早期兜底 |
| **B+** | B 的闭环 + 人工只做最后一道挑图 | 自动化处理 90%，人只看一眼 | 需要后台页面 | **推荐** |
