## 优化方案与上线边界

1. **P0 原样直传和多附件选择。** 仅以用户提供的原始文本形成直传字段。以原件 ID 和本轮附件顺序绑定必须使用的 Logo、原稿、风格和产品图，不任由前置模型删必选素材。多附件的规划仅需轻量预览，最终执行解析经授权的原件。记录预览体积、网关耗时、模型时延与出图输入角色。现有样本只证明压缩后的重试成功返回，408 的具体限时层还需请求日志。只在本轮「13 张和最后 Logo」这类明确全集请求补齐候选合同，并覆盖用户明确只用第二张的优先级。[火山方舟 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh) · [腾讯云 HTTP 访问服务](https://cloud.tencent.com/document/product/876/122894)
2. **P1 明确重绘范围与保护项。** 前置模型读原稿，建立段落、标题、实物与画面区域的对应。单次提示以用户指定的修改和原稿硬约束为核心。局部只贴 Logo 时沿用原像素。整体换风格时允许 5.5 共同设计，再验证所有原件是否出现。只要要求保真，则输出前核对标题、段落、热线、原件和版式。图层 OCR 适合规整文字，按当前偏好保留作后续选项。[Seedream 5.5 官方教程](https://docs.volcengine.com/docs/ark/seedream-5-5?lang=zh) · [OpenAI 图像编辑指南](https://developers.openai.com/api/docs/guides/image-prompting)
3. **P1 少字与长文精确排版。** 少字且用户指定内容时，优先走现有字体渲染组件。长文仍让模型设计视觉底图或局部视觉区域，可用已确认文字排版，保留图标和场景。禁止退化为整张固定办公文档模板。现有 bf-image 已固定 Satori 0.63.2 与 resvg-wasm 2.6.2，分别负责排版和 SVG 转 PNG，上游 MPL-2.0。需按字体覆盖、最大画布、实际阅读距离、WASM 冷启动和字体资源验收，当前无新增依赖。[Satori](https://github.com/vercel/satori) · [resvg-js](https://github.com/thx/resvg-js)
4. **P2 减少策略重复与维护版本漂移。** 先让每个入口只有一份最终图片请求和一个可观测路由。简洁提示以受众、主题、用户显式风格和必要文字为主，相关场景和设计元素由内容决定，窗口对未确认风格可高饱和有层次。旧 IPA 需要的回程字段保持兼容。按真实用户的原样、局部、重绘、长文本和图册验收后再部署，避免把旧备份覆盖生产。
5. **已处理与回滚。** 候选只识别这类用户明确全用指定图组的表达，新增原话回归。保留最新 IPA 原件和现有生产设置，代码回退取 d8a1ca21。本轮仅发布审查文档与服务端源码候选，业务和真实账号无变更。后端全量回归 1045 项通过，0 失败。
