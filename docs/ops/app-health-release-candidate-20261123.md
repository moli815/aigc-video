## 修改与边界

- 客户端集中声明附件上限，单轮允许 16 个附件图片。较大的集合生成编号图册给规划模型，原件保留在资料库，工具选择仍用原附件顺序。明确要求全部素材的单图生成，对上限以上的附件使用编号图册，并在识别出 Logo 角色或明确文件名时额外传原始 Logo。Photos 导入部分失败给明确提示。纯素材操作关掉自动联网补查；要求核实价格等外部事实保留研究路径。
- 服务端将标签工具回程接到标准参数定稿和唯一结束帧。标签会保留素材索引、角色和已检索引用；不可解析的空标签进入一次受控修参。用户明确全部引用时，补齐当前已可见的素材；历史引用冲突有明确保真的请求进入修参，避免静默丢弃。同步写入确认后恢复账号图片索引，索引失败记录状态，不覆盖已提交的结果。
- 商业出图与程序排字使用不同的最终编译。重排尊重原稿和目标比例；明确要求丰富画面时用材质、光影、局部特写与无字图解表达。当前样张证明新增流程标注能被模型自己画出来，候选已将禁止新增文字写进重排执行规则。
- 管理工作台缺账单窗口或覆盖字段时仍能渲染客户区，未知应付显示待同步。前台数字使用现有财务 API 口径。
- 一轮的基本密度与风格默认由内容决定。精选产品原件像素、透明 Logo、源截图具体保护仍应走已有资产保护合成。超过 5.5 十张原图上限时，产品集合以图册传入，不能宣称供应商收到 14 个独立文件。

## 复测与发布

1. 前置：取 before.json 同版本备份，运行 scripts/prepare-poster-delivery-20261123.py，校验允许的源码文件、依赖与函数入口。若线上已更新，以新的备份逐块审查，不能上传过期候选。
2. 在评估目录先生成与输入哈希对应的 ImageGen 基准；运行 real-planning.cjs、capture-provider.cjs，再运行 real-images.cjs。供应商发生不确定结果时先核对账本，不能自动重跑。失败图只改可定位的问题后再测。
3. 跑会员/同步/组图/权限的后端回归，随后 GitHub macOS 构建、iPad 模拟器单测及关键 UI 测试。发布产物指向具体提交。SwiftTool schema、旧会话、上传下载、SSE 终止和本地错误提示都要验收。
4. 上线前检查只读探活、当前账务与明确授权的候选包。备份并使用 SCF 安装依赖关闭的上传方法，核验下载包与候选一致。管理端保留对应 live JS 备份。出包按用户授权的 GitHub 编译路径交付，机上安装后的 SideStore 签名与网络仍以用户设备状态为准。
