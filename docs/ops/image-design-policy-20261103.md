# 商业图片：上下文、内容策划与默认视觉策略

日期：2026-11-03。只更新服务端 bf-api / bf-image，兼容已寄出客户端，不生成 IPA。

## 为什么调整

用户的 ChatGPT 参考图是行业参展行动信息图，旧 App 产物偏公司现场预约广告。两者首先是交付目的、信息覆盖与具体行动不同，不能只归因于画面简约。客户原始完整请求字节未取得，不能断言全部由上下文截断导致。

代码确有两类问题：图片工具最终只把整理后的请求交给 Seedream，不会自动附带聊天语境；语义缓存此前不区分系统记忆/风格，且带工具的请求可能命中普通文字缓存，绕过新工具规划。App 发送最近 40 条消息且有文本预算，服务端不能恢复客户端已经裁掉的原文或根本没上传的素材。

## 参考的公开方法

- [OpenAI 图像提示指南](https://developers.openai.com/api/docs/guides/image-prompting)：从交付用途、场景、构图、准确文字、素材作用及保留约束组织请求，多轮明确本次改动。
- [OpenAI 图像提示示例](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)：针对信息图、商业图及编辑分别组织具体规格，而非统一审美形容词。
- [Anthropic Canvas Design](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)：少文字艺术表达有适用范围，不可强套到高信息密度商业攻略。没有安装或执行外部 skill，也未证明该上游文件是本次线上问题的直接原因。
- [Seedream 5.0 Pro 官方说明](https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=zh)：保留现有 Pro / Flash 与原生提示优化契约；借鉴 OpenAI 公开方法不等于切换 OpenAI 模型或取得 ChatGPT 内部提示词。

## 模块与请求流

1. `commercial-image-guidance` 识别本轮商业设计及短回复承接；明显转向合同、天气等任务时停止沿用。v5 保留准确文案和布局契约。
2. `image-design-policy` 统一用途与视觉策略，建立本请求已有近期对话的有界索引。用户信息与未确认的助手草稿分开，最新改口优先；不复制系统秘密或图片像素，不查其他账号。
3. `image-tool-schema` 仅为商业 `image_generate` 要求 `structured.design_brief`，包含用途、受众、目标、读者问题、视觉方向与信息密度。原工具、来源选择和保真字段保留；局部编辑不增加该必填要求。
4. 旧 App 将既有 `structured` 字典通过请求编译器传给服务端。没有新增客户端要识别的工具名或顶层协议。无字底图分支仍由旧 App 清除可见文案并传 `text_mode=overlay`。
5. `shared/image-design-brief` 在 bf-image 内将允许字段编译成内部执行简报。只用于 generate/reference，不重排局部编辑；无简报的旧请求保持原行为。overlay 强调无字底图，简报本身不是可见文字。真实咖啡样例暴露出原生请求将全部文案摊平成普通行、丢掉 role；现追加完整带角色的定稿，明确品牌 label 不可替代 title、body 不可只取前两句。overlay 与局部 edit 不使用这份原生文字契约；字段字典等旧格式仍走原兼容路径。
6. 带工具请求不再命中普通文字缓存；普通文字缓存纳入系统上下文摘要。没有额外增加一次前置 LLM 改写调用，但工具请求可能少一些缓存命中，设计指导也增加输入 token。

默认不锁定蓝色科技、黑金或少字留白。行动指南强调决策、依据、动作、结果；产品宣传强调可信产品/使用场景；服务说明用关系和流程；摄影强调物理一致性；插画与品牌按用户要求决定。用户明确极简时仍允许稀疏内容，不能机械堆字。聊天简短规则不再被当作正式海报内容上限。

## 验证与实际边界

- 本地全部后端回归 **481 通过、0 失败**，包含主标题/品牌区分、正文逐项保留、overlay 和局部编辑排除。
- 隔离账号、真实前置模型、三组多轮请求：
  - 行业参展指南：11 项 / 1011 字，purpose=action_guide、density=dense，包含具体合作对象、问法、三天行动、筛选与跟进；没有虚构馆号，没有被助手的预约广告草稿带偏，耗时 11.7 秒。
  - 最新改口极简广告：3 项 / 28 字，density=sparse，精确保留指定标题、副标题和电话，耗时 6.5 秒。
  - 新行业咖啡海报：10 项 / 152 字，density=balanced，采用暖光写实摄影，不夹带安防内容，耗时 8.6 秒。
- 三组均取得可执行的完整工具参数，不是只检查提示词字符串。人工复核仍发现指南文案有偏长、建议语气偏强的空间，不能把字符数当作商业质量分。
- API / 图片健康接口 200，匿名会员接口 401。临时验证账号清理，正常调用审计保留。
- 已下载线上代码核对：业务变化只包含 API 四个文件、图片两个文件。npm 另调整 node_modules/.package-lock.json 中 license 元数据（15/10 项）；已单独复核，无版本、integrity、resolved、dependencies 变化，所有其他依赖文件字节相同。
- Windows 没有运行客户 UIKit 排字，因此这不是已寄出 App 的端到端视觉验收。当前源码的 TextIntentDecider 只有用户明确要求逐字准确才启用排字，不能宣称文字多就自动切到程序排字；服务端这次没有伪造用户原话强制切换。此前含乱码的原生 Pro 参展示例仍为 **deliveryAccepted=false**，不能因本次规划改善将其改为合格。
- 另做真实 Pro 咖啡原生图验证：第一张摄影材质/自然光有表现，但漏新品主标题和风味最后一句，故未验收；据此补上述原生角色契约，而非盲目重复同一个提示。样例与后续复核记录在输出目录，不能只凭生成成功当作完整交付。
- 补丁后二次真实 Pro 样例耗时 58.9 秒，目视逐项核对 10 个文字条目：品牌/新品主标题分别保留，风味三句、到店体验、适合场景与尾栏齐全，当前单张样例通过。尾栏对比度仍可提高；这是人工复核，没有自动 OCR 逐字校验，不能证明高密度参展图或所有样例都过关。两次 API 返回 cost 均为 1.2（接口计费字段，不拿来等同平台实时账单）。
- 不承诺 Seedream 与 ChatGPT 生成质量相同，不承诺原生中文永不出错；不把几何合法、一次规划成功或单张漂亮图当作全部任务通过。
- 旧包组图/source=both 素材未完整上传的边界仍在，见 `legacy-reference-audit-20261103.md`，本次没有凭空补图或跨账号借图。
