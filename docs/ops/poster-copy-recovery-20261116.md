## 实际发现：不是简单加粗/变细/升像素就能解决

本轮复用原有真实失败海报，只追加一次5.5拆层、一次现有视觉模型补读，没有重新生成海报。先核源码，再核官方契约及实际开源代码。

1. **一个透明图层可以含多个栏目，原组件却按整层匹配一段正文。** 已改为原生行坐标的空间分组和连续行唯一匹配，支持交错多栏、同层多段。不复用同一行，不猜缺失字段，不删除必需正文。
2. **浅底黑字的检查不适用于深底白字。** 新增前景/背景独立测量、对比度及残留字形检查；复杂纹理不靠放松平面背景阈值通过。官方透明字形可验证时，按真实alpha做非矩形遮罩，只从干净底图取原字形附近像素，不整块白盖或统一改成PPT分栏。
3. **拆层识别结果会漏行。** 新样本返回2图、约30.3秒。真实透明层有88,863个明显字形像素，其中18,046个没有识别坐标，约20.3%。这些不是原图内容缺失：人工核对原图，底部四步及合作分工首行本来就有字。不能把“没识别到”当成“没有”。`native-text-coverage.js`用已有OpenCV检测漏识别墨迹与连通区域，几何来自实际像素。
4. **补读能找回漏行，但仍不是整图合格。** 现有视觉模型只看10个实际切片，不提供期待文案、不接受模型新坐标；1.794秒补读出“本地实施、现场”和四步文字。只接受既有区域ID，新增坐标/漏ID/重复ID/null都拒绝。实际读图成功不能从模型配置名推断它不支持视觉。

## 本轮实现及验证边界

- `native-copy-refinement.js`：同层多段、多栏唯一匹配；短边决定字号下限，宽海报不强迫正文升到40px；保留英文空格；不覆盖未选栏目；可选保留原层级尺寸；普通正文Regular400，明确的栏目保持Bold700。混色强调仍保守拒绝，只有可选原生尺寸模式能将相近中性色阴影统一为较清楚的墨色。未全局使用Thin。
- `native-text-coverage.js`：支持图层独立分辨率，通过官方parent box映射到输出底图；检查实际alpha与识别覆盖，而不是相信OCR文本数量。
- `native-copy-transcription.js`：补读只选真实区域；不使用模型自由坐标或把期望文案当识别答案。冒号转换行、列表分散为标签须显式允许；保留原生数字徽标还须原图视觉验收，默认拒绝。不是逐字准确需求下可默认删标点的权限。
- `native-copy-task.js`：生成后的独立持久化文字任务。账号与请求ID隔离，冻结原图hash/正文/字体政策/模型与原调用成本；只存私有素材描述符，不存签名URL/base64；付费拆层先持久化dispatched，未知结果不得重发；保存图层后可跨实例继续本地渲染。局部连续失败最多3次后待处理。质量失败保留成本与素材，不返回未经修复图冒充成功。
- `image-billing.js`：支持将多阶段供应商成本合并为一次原子会员结算，并保存各调用的分摊和估价性质；同一账务事件还核对账号，不能仅因金额一样就复用另一个账号的事件。估价不冒充供应商已出账金额。
