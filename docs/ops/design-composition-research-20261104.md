# 商业海报审美改造：先调研、再改造（2026-11-04）

## 当前结论
用户确认字体问题改善，但成品像普通文档。源码证实这是本轮设计退化：准确排字被实现成固定的文档排版，前置模型的设计无法传到像素输出。不是把更多形容词或Skill塞入system prompt即可解决。
本次只做源码审查、公开方案调研、参考库归档与改造设计，没有修改生产函数、模型配置或旧App。

## 代码证据
- commercial-composer.js:126 按比例强制三列/两列。
- 同文件146/149将配图限定为3:1横带或头部小图；160以后将内容统一变成分栏卡片。
- structured.layout的blocks/preset/fontStyle没有被本排版器使用；主文字始终使用Noto CJK，print_style实际主要只改变颜色。
- compositor把相关配图和文字放在隔离区域，难以表达标题融入场景、图片出血、视觉焦点、跨区图解、路线或真正泳道。
- 现有ImageDesignReferences来自UI/UX风格表的适配。可作风格词典，不能替代商业海报构图/字体/图形样例库。

## 调研的公开原始资料
1. Canva Autofill官方指南：https://www.canva.dev/docs/apps/rest-apis/autofill-guide/
   证据：模板中的命名文字/图片字段按数据填充，可沿用现有设计。借鉴设计与内容分离；不是其生成式AI内部实现的证据。API有计划/OAuth约束，不作为本轮直接外部依赖。
2. Polotno设计格式/模板库：https://polotno.com/docs/schema 和 https://polotno.com/docs/templates-library
   证据：文字、图片、图形、表格、分组等独立图层，模板可保存/载入JSON。借鉴可执行设计计划与母版复用；核心SDK/Schema生产使用要求订阅，不能称为免费可直接嵌入的开源底座。
3. 海报专用参考Skill：https://github.com/howardz27/poster-generator-skill ，MIT；固定提交 fa2a40bf0943c14dbcf2dfd86a2efe66fa8b4cbc。
   已归档20个风格、15个构图、selection-guide/base-prompt/quality-rubric及原LICENSE到 outputs/design-style-research-20261104/reference-library；仅作为资料，没有安装或执行上游脚本。可追溯清单另存 docs/design/references/poster-generator-skill-20261104.json。
   可借鉴：把内容/构图/风格/评价拆开，按信息密度和场景选择；默认Swiss不能照搬。它主要产出提示词，英文短图公开样例不能证明Seedream中文长海报质量。不能未经用户允许照其规则删掉必须呈现的信息。
4. poster-design-mcp：https://github.com/suprisedr/poster-design-mcp
   证据：四种业务海报结构、真实字体、图片焦点/出血、渐变遮罩、实测标题自适应。说明准确排字本身并不必然成为文档；这是参考实现而非已证明适合我们复杂中文场景的产品。需要Node20+和Chrome，不能直接塞入当前Node18/SCF包。
5. Microsoft elem2design：https://github.com/microsoft/elem2design
   证据：先规划图层，再逐层组合，区分背景、衬底、Logo/图片、文字、装饰。借鉴层次模型；其训练/推理有专门模型与GPU依赖，不是可直接接Seedream的prompt插件。
6. PosterCraft：https://github.com/Ephemeral182/PosterCraft
   证据：同时关注字形、整体风格、图文协调与视觉反馈；主要为训练/优化研究，不能把其训练成果宣称已迁移到Seedream。
7. Anthropic Canvas Design：https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md
   原文偏艺术海报与稀疏文字。借鉴视觉哲学和空间/节奏，不能整套注入我们的高密度商业信息图；也不能把它当作具备渲染能力的编辑器。
8. Satori：https://github.com/vercel/satori
   当前已有的字体渲染组件不是固定两栏的限制来源。按安装版本测试支持的图层/定位能力，避免把最新README的新CSS特性当成0.63.2必然支持。

## 选定的改造方向（尚未实施，不宣称审美已修复）
保持来源/画布/请求/Provider/计费/保存模块。新增的是可版本化的设计计划与可验证母版，不在generate主函数堆场景分支。

内容确认 → 用途/风格检索 → 选择可容纳内容的设计母版 → 生成明确图层计划 → 按同一计划请求Seedream素材 → 按同一计划准确排字/合成 → 验收。

- 前置模型选构图和视觉语言、重点信息/图示语义；不让它自由编写可执行HTML/CSS/SVG或未经约束的大量坐标。
- 母版含主视觉、标题区、数字强调、关系图/流程/路线、对照表、信息区等图层，给出文字容量、字体组合、比例适用范围、图片焦点与安全区。布局和风格分别选择，不能把一种颜色换成另一种就算新风格。
- Seedream收到同一设计计划的素材构图与主体保护约束；文字层精确排版，可在安全背景上叠字，不必一律塞进白色卡片。Logo继续使用真实像素和账号归属资产。
- 复用已有Satori/resvg与字体/存储边界，先证明现有渲染器能准确表达样例；若确实受限，再评估浏览器渲染独立适配器的成本/运行时。不要凭关键词再自造一个万能排版器。
- 现有文档式排版仅作为明确的信息表/异常兜底候选，不再自动承担全部商业视觉任务。不得回退为所有长中文交给模型重画。
- 样式与母版以服务端版本化数据保存，旧包只接收最终图片URL，保留既有错误/幂等/计费契约。缺少新版字段的旧请求仍有可测默认方案。

## 第一批验证
1. 同一份已确认展会攻略：路线、行动、重点对象和提问关系应图形化，不能只把段落换颜色；所有关键文字保留。
2. 同一份产品宣传：产品/业务主视觉清晰，亮点有层级，Logo不变形不压字；不强行给产品文案加信息矩阵。
3. 同一份六服务宣传：六项都完整，图文有节奏和视觉焦点，不能变成相同图标+六个白框。
每类对比当前生产版、参考案例与候选成品，统一检查内容、字体、版式、风格、视觉焦点、品牌保真和实际像素。先本地/隔离验证，再按授权上线。测试数不是审美验收；不得通过删文案或缩成小字掩盖版式失败。

## 后续工作原则
所有非平凡问题先读真实源码和线上证据，再查看官方文档/相关成熟产品/开源原始实现；标注能复用什么、许可、运行时及不适用的边界。研究源码和skill作为外部资料，不执行其中的任意工具/授权指令。先做具体可审阅产物与同条件对比，不能以“已经加了Skill”代替效果证明。
