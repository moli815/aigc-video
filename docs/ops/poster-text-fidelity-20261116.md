## 源码与真实响应确认的问题

1. **字形错误不等于 OCR 字符串错误。** 生成式模型画出的中文字可能大致可读，但笔画粘连、断裂、扭曲。识别模型按上下文读对，不能证明实际字形正确。仅把 prompt 改成“更细字体/文字清楚”不是确定性修复。需要把确认原文交给真实字体渲染，并验证去字、落位和保护区域。
2. **拆层与生成的 size 契约不同。** 此前候选把生成可用的 WxH 用于拆层，真实返回 HTTP 400 `InvalidParameter`。官方拆层接受 `auto/1K/1.5K/2K`；当前共享请求构造器使用 `auto`，仍验证实际底图尺寸，不能靠重采样掩盖坐标变化。保留失败回执，执行脚本已改用同一构造器，不能再发已知错误参数。
3. **识别坐标不等于文字已经从底图去掉。** 对用户认可图做了一次有上限的真实拆层：1024×1536，85.443 秒，2 张输出，估价 ¥0.31。透明层含 48 行识别信息，但底图仍留着多段能力正文和其他文字。原图/底图已目视核查；不能看到 OCR 数量就直接盖字。图层是 1024×1189，亦不能假设它和底图分辨率相同。
4. **原生返回还会漏掉或多写文字。** 此前实际 App 候选 app-6 中出现重复的“2”步骤和额外乱码段；同时受保护素材验证有 OCCLUSION/Logo 区域不可信和置信度不足，不能把失败都归成文字问题。本轮完整文案模式新增“未解释 OCR 行不得保留”门禁；局部编辑保留未选正文，不把全图门禁误用于局部修字。
5. **匹配不能把数字、品牌、分隔关系也当错字修掉。** 中文有限编辑距离只用于唯一、近似的识别匹配，最终仍渲染确认原文。增加 4 字标题单字识别错误支持；步骤数字、金额/型号中的 Latin/数字及标点结构必须一致，避免把另一个字段误当同一段。
6. **确定的 4xx 不能永远显示“确认中”。** 候选拆层适配器把明确客户端拒绝和传输未知结果分开：400–499（408/429 除外）进入持久化拒绝，不再付费重发，保留已发生主图费用；未知请求仍禁止自动重发。该修复有本地状态回归，生产未切换。

- [OpenCV 官方文字检测与去除](https://opencv.org/text-detection-and-removal-using-opencv/)：借鉴检测/遮罩/Telea 流程，使用项目已有 4.12 WASM，Apache2；不新装服务。该通用处理不识别语义，不把所有灰色图形都当文字，所以本实验只用人工核对区域。
- [Satori 实际实现](https://github.com/vercel/satori) + 项目既有 resvg：实际加载字体并输出 glyph path；Satori0.63.2/resvg2.6.2、MPL2，Node18兼容，固定依赖不升级。Noto CJK Regular/Bold 为 OFL1.1。没有引入整套 PPT 模板。
- [PaddleOCR 版面恢复实现](https://github.com/PaddlePaddle/PaddleOCR/blob/main/ppstructure/recovery/README.md)：Apache2，借鉴“文字、区域、图像分开重建”的边界。该 Python/模型运行时没有安装或实测；用户明确暂不接独立 OCR，不能冒充已接通。
