# 上传新 Logo、附件序号和历史品牌资料

## 修复前的现场

普通测试账号通过会员 App 使用的同步接口同时上传产品图、Logo 和「图一是产品图，图二是我们公司的 Logo」。推送成功，拉取也返回两份原图，品牌索引却为空。该账号已经启用新生图简报，旧的图片工作流和旧的品牌功能均未开启。前一轮直接运行过索引函数，证明了索引可用后的行为，没有覆盖真实同步入口。

用同一段原话在旧索引函数回放，逗号让图二的用途被归到了图一，换成分号才会识别正确。另一次回放使用「用我刚上传的公司Logo，给上一版加上」，旧版将这句话判成了要求搜索企业历史 Logo。

## 处理和验收

| 优先级 | 涉及的链路 | 用户可见的结果与验收方式 |
| --- | --- | --- |
| 高 | 会员上传 → bf-api 同步 → 历史品牌索引 | 索引入口与当前使用历史品牌原件的生图功能对齐。同步后从正式拉取接口核对，只应标记第二张。文件晚于消息到达时，从本账号最近的消息中重新关联文件，保留附件已有文字。 |
| 高 | 多图声明 → 资料库 | 每个「图一」「附件13」「第十三张」只读取自己位置的声明，保留原始上传顺序。测试覆盖同句的产品与公司 Logo、平台截图与 Logo、空槽和多种标点。 |
| 高 | 用户说用这次的 Logo → 编辑已生成的海报 | 当前附件明确是 Logo 时，保留规划器提供的上一张成图和当前上传原件，以及已有局部编辑参数。服务器自动补取历史品牌的条件收窄到明确的底图或历史素材请求。 |
| 中 | 旧会话、多品牌或搜不到原件 | 旧索引会指回同账号原始用户消息重新核验角色。没有索引的近期记录也可用用户的原始声明核对。两个实际原件时要求缩小范围。明确执行过的图片搜索没有返回有效原件时，请用户补发或指定；只执行文字搜索不算找过图片。 |

客户端检查了 iOS 图片工具参数对当前附件、上次成图和历史文件的处理。正式验证通过 HTTP 推送与拉取，复用了已安装版本的协议。用户原话和素材顺序是验收输入。确定性回放检查送入下一步的调用参数。没有调用付费模型或在 iPhone、iPad 上进行真机视觉复测。

## 存量与边界

读取旧标签时会校验来源。产品图被错误标为 Logo 而正确原件同时可见时，可通过原声明选回正确文件。线上没有批量改写客户历史数据。旧 App 已缓存的文件摘要可能仍带旧标签。没有索引且文件或声明超出近期窗口时，仍取决于实际检索结果、用户是否指认过该素材，以及原文件是否已同步。不能据此承诺找回任意久远的资料。图中微小编号与商标像素保真另项验收。

## 产品对照

Adobe Express 让用户选定或切换本次设计使用的品牌；ChatGPT Images 支持用户上传图片并说明具体编辑。借鉴的是当次选择优先、编辑针对明确原图的交互语义。本项目复用自己的 Node.js、账号私有文件和现有 App 工具协议，没有复制外部代码，无新增第三方运行时或许可证。[Adobe Express 品牌选择](https://helpx.adobe.com/express/web/ai-assistant/create-on-brand.html) · [ChatGPT Images 编辑说明](https://help.openai.com/en/articles/11084440-images-in-chatgpt)
