# BossAI 产品链路说明与代码审查

记录时间 2026-11-23，北京时间。面向产品、运营和接手开发。发布基线是 19:16 的 iPad 包，服务端以 19:33–19:34 下载核验的归档为准。

## 产品现在怎么跑

| 用户要做什么 | 数据走哪里 | 负责的代码 | 常见风险与排查入口 |
| --- | --- | --- | --- |
| 登录、续费并使用会员权益 | App 登录换会话，读取 /me；服务端按账号和会员状态放行；管理员在后台改套餐与行为开关。App 缓存配置。 | HostedAccount.swift、bf-api/index.js 的登录和 requireMember、web/admin.html | 配置缓存会有时差。区分登录过期、会员到期、用量不足和云服务错误。后台隐藏按钮只改善操作，权限由服务器检查。 |
| 普通聊天、专家与工具 | App 送当前问题、近期消息、历史摘要及工具清单；bf-api 决定路由并流式返回正文和工具事件；App 收到完成标记后保存。 | ChatViewModel.swift、ChatService.swift、bf-api 的 finalizeImageCalls 与流保护 | 旧事故的核价失败发生在模型之前，模块不匹配和空流发生在收流期间。按请求 ID 查到具体阶段；HTTP 200 可能只有不完整片段。 |
| 上传产品图、大屏、Logo | 本次附件预览给规划，生产原件保存到账号私有云存储。服务端校验原件大小、完整性和归属，短时签名链接只供读取。 | CloudAssetStore.swift、bf-api/domains/foundation.js、shared/asset-store.js | 预览或图册能解释内容，不能代替所有单张高清原件。老包未上传的素材无法自动补回。 |
| 使用之前的资料 | App 提供近期消息、摘要与本机检索结果；云端按账号查同步的记忆和经过绑定的图片原件。用户明确的本轮资料优先。 | account-context.js、account-image-memory.js、image-reference-store.js | 品牌文字与 Logo 是两种资料。没有账号内原件和用户声明时可能只有公司名。旧海报活动、日期、未经确认的口号不能直接复用。 |
| 新海报、参考图重做 | 聊天模型将用户要求、要印的文案、素材顺序转成工具参数。App 发送 /img/image；bf-image 按内容、比例和样式生成。 | reference-text.js、intent-contract.js、poster-delivery.js、bf-image/index.js | 视觉模型会误判旧稿、漏标签或重画图标。准确文字层只能作为有条件的兜底。风格选择不应绑固定网格，用户改风格时优先。 |
| 精确贴 Logo 或改图 | 有局部范围和原附件的精确替换走原本地合成。新海报的品牌原件候选走服务端私有引用和原件合成，5.5 负责画面。 | PreservedAssetWorkflow、poster-brand-guidance.js、image-protection-runtime.js | Logo 必须能验证原件。角落不能挡住正文。无法安全合成时现有模块拒绝交付，不应把替代图形标成原件。 |
| 组图和失败重试 | /img/series 有独立任务、张数、素材清单和请求标识；再次查询或用同编号重试可避免重复收费。 | bf-image /series 路由、image-job-claim.js、图片额度台账 | 组图与单图的协议和输入上限不同。上游已生成但回程超时需先看结果状态和账单。 |
| 管理员看用量或改开关 | 管理页请求账户、财务、设置接口。即时估算、平台确认费用、用户扣除金额分开显示。 | web/admin-console-20261029.js、bf-api/domains/finance-report.js、bf-image/image-billing.js | 审核人和管理员权限不同。样张回放出现一次客户端请求引发两次模型调用，成本必须看模型台账，不能按交付图张数估算。 |

## 这次定位与实现

- **换风格误用原图**。此前“换一种风格”没有命中旧稿识别，附件被描述成实拍主视觉。参考文字读取会从历史消息拿到第一张图。候选按当前单图选择原稿，改版时保留可明确读出的术语与内容。本轮明确改文案时继续使用用户的新文案。对照先看标签遗漏、术语重复、产品身份、实际宽高与画面布局。
- **节气海报缺 Logo**。11 月 22 日“小雪”当轮无附件。旧路径仅带入品牌事实，未复用标志图。本次只针对新建公司海报，按账号核对历史文件索引、声明消息和私有入库资产。默认 Logo 放在安全区域，指定角落时尊重当轮请求。沿用现有抠图及避让模块。新自动品牌功能跟随现有历史参考策略里的 `posterBrand` 开关，启用时需 API 和图片函数均支持。局部编辑和已选参考图保留现有路径。
- **设计规则由两处发出**。新版会员常规设计由服务端下达默认风格。App 精确编辑仍保存原件、范围和多图顺序约定，旧服务端和自填密钥模式仍使用客户端原设计指导。模型最终提示优先带用户明确的当轮风格。当前同账号的明确审美偏好由上下文提供，未注明已认可的旧海报不强制沿用。
- **商业排版仍要目视**。5.5 能整图提案、编辑、拆层。输出小字即使接近正确也可能糊、变形。验证时同时看文案完整、文字清晰、主次、素材、背景内容、用户明确要求。一次对子不能证明广泛一致。

## 参考与适用边界

- 火山引擎官方 5.5 说明支持多参考输入与拆层。短视觉说明、原文交给文字清单。拆层富文本识别仅能用于符合条件的文字层，需额外调用，因此本轮未增加默认拆层费用。 [Seedream 5.5 教程](https://docs.volcengine.com/docs/ark/seedream-5-5?lang=zh) · [图片 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)
- Penpot 的共享组件保留资产身份和引用，适合借鉴品牌图形作为独立资源。本轮只借用分层思路，不导入 Penpot 代码或运行时。 [设计资产](https://help.penpot.app/user-guide/design-systems/assets/)
- sharp 的开源合成接口展示确定性位图叠放。项目已有 PNG/JPEG 与 OpenCV 合成，保留现有 Node 运行依赖，本轮没有引入 sharp。 [sharp 合成源码和契约](https://github.com/lovell/sharp/blob/main/docs/src/content/docs/api-composite.md)

## 安装包单独验收

iPad 和 iPhone 共用 com.bossai.app，部署目标 iOS 17。变更涉及视觉提示拼装，不涉及数据库模型、Keychain 标识、权限清单或签名配置。需核验正式包名称、版本构建号、Info.plist、可执行文件、Xcode iPad 测试和 Github artifact。现有流程输出待 SideStore 重签的 IPA。模拟器与 ZIP 完整性无法代替客户设备签名安装实测。



## 当前样张与上线状态

- 原客户回放用例分别是“帮我把这张图片重新帮我生成一张换一种风格”和“今天是二十四节气里面的小雪，你帮我们公司做一张宣传海报”。对照使用同一原稿或经真实声明绑定的原 Logo，基准端提供了与场景相关的确认事实，App 候选走同会话历史的实际 HTTP/SSE。两边的历史实现不同。新版 IPA 的 UI 仍由 GitHub iPad 模拟器单独检查。
- 摄像头第三轮保留系统拓扑、PC/手机端和 12 个功能项，原宽高比误差小于 1%，去掉了前轮虚构的价格和联系方式。目视仍发现“红外探测器”重复一次及局部界面细字；基准的图标配合主体更醒目，同样有重复主标题。该样本不支持任意内容零错字。
- 小雪在真实隔离回放已同步、取得并验证原图，Seedream 生成草稿成功。前几次在调用图像定位后返回 409，客户没有看到成品。候选进一步为单 Logo 使用只输出内容占位的几何操作，老图层和准确合成约束保留。该路线在确认最终输出前保持配置关闭。
- 本轮测试账号及测试端素材独立于客户。隔离配置只存在于本地进程。最新正式服务器没有在测试过程中切换。
- 新 IPA 的设计移交由新能力字段 posterDesignByServer 确认。旧服务不会返回此字段，客户端按旧方式继续。签名、商店权限、应用标识和数据模型没有改动。

### 品牌落位诊断

仅标注占用区域仍返回 409 的根因已实测定位。视觉模型把位置数组按左上角、右下角返回，旧契约按左上角加宽高校验，导致正常框被判越界。新的单 Logo 子契约显式使用 boxes_xyxy，服务端归一化为宽高，验证上下界，并允许接收已归一化的回包。常规大屏及 UI 合成仍走原有角点和文字复核。单 Logo 定位仅能验证几何，翘边、对比度和画面脏字由实际成品验收。生产开关仍未开启。
