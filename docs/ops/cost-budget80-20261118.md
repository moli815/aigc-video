# 166 元会员成本预算与账务迁移（2026-11-18，内部）

## 指令与真实基线

用户要求 166 元会员提供 80 元实际模型成本预算，按成本一倍扣额度；历史不能多扣，不能重复扣，不能漏掉实际调用。80 元为内部成本信息，不写进公开套餐宣传。只改服务器，兼容已寄出的会员登录 App，不出 IPA、不改员工端。

只读审计发现线上 Plus 池为 **136 元、两条倍率均 2**，有效模型成本约 68 元，并非口述的 120/60。当前仅一名有效 Plus 客户。本周期锚点 2026-11-17T03:36:10.232Z，15 条流水：旧额度扣减 2.72494048 元、记录成本 1.36247024 元。166 元收款价格、会员期限、账号不变。

## 真实账单的证据边界

原有计费使用真实返回用量、缓存 Token 和经账单核验的单价。`supplierBilledCny` 在当前 15 条流水均为空；它们不是逐笔最终账单。火山和百炼收集器保存的是平台汇总账单，`complete` 代表拉取分页完成，不代表已完成最终结算。不得把测试、管理员或其他调用方的费用强行分给客户。

- 百炼推理通常在调用结束后 2～10 分钟出账，按 API Key、模型、输入/输出等维度分账；出账不等于现金扣款。[官方账单查询](https://help.aliyun.com/zh/model-studio/bill-query-and-cost-management)。
- 火山单请求用量接口以响应体 `id` 查询，返回用量和计费状态，不能凭它直接获得每次的人民币应付额。[官方单请求用量接口](https://docs.volcengine.com/docs/ark/get-inference-request-usage-api?lang=zh)。只读检查最近 10 条图片调用均未保存可用的响应体 ID，本轮不能凭请求头 logid 冒充它；没有重新付费调用取证。

因此本轮提供**成本 1 倍暂记、可追溯台账、未知成本预留**；不声称逐请求最终账单对账已完成。历史换算也是基于已有用量成本的暂记转换。最终账单退款/补差仍需取得可验证的归属和完整用量覆盖后实现，不允许平均分账猜归属。80 元是模型预算，不是扣除云服务等其他支出后的净利润承诺。

## 根因及修改

1. `shared/usage-settlement.js`：迁移账号的可信 `costBudgetPolicy` 覆盖运行中旧请求冻结的 x2 快照；账户、调用状态、流水与预留释放同事务；重复结算只记一次。
2. `shared/model-call-ledger.js`、`shared/cost-budget-admission.js` 与 API 接线：原来辅助分类/审稿等调用只有成本台账，未必扣额度。新成本模式将可核价的聊天调用逐次结算；UTF-8 输入字节上界、消息开销、最大输出和非缓存单价预留预算，事务内检查本账号池及其他并发预留。未知价格/缺台账不发出付费请求；未知结果不自动当免费释放。
3. 图片 `customerPriceOf` 不再逐笔舍入到分，避免小金额被错误舍入；`image-billing.js` 在事务内按最新账号政策结算，原先普通图片 `estimated:false` 改为诚实的待账单核验标记。调用账本使用真实落账金额，防止旧请求标成 x2。
4. `image-cost-budget.js` 为单图、同步组图、异步组图、旧重试提供账户内事务预留；父组图在派发前把预算切给子图，取消只释放未开始部分，已发出的子图仍有保护。成功落账及子图预留释放同事务，明确失败释放，未知结果保留。
5. `native-copy-budget.js` 计入并发聊天和普通图片预留；图片 HTTP 使用 `AsyncLocalStorage.run`，防止账号计费策略跨请求污染。
6. `shared/cost-budget-migration.js`：完整周期流水与账户对账，范围/归属/重复/缺成本/CAS 防护；保留原流水，新增负额度调整与迁移审计，拒绝不完整证据。源码的周期、开通及续费路径漏清 `proUsedCny`，导致客户 Pro 分类 3.291975 大于本周期聊天 0.58494048；本轮仅据完整流水修复这个不可能的旧分类计数，后续开通和续费也清零。保留 DSH 审批代码，只对线上原模块追加此字段。
7. `quota-percent.js`：旧 App 用剩余百分比决定能否发送。最后少量余额被 `Math.round` 舍为 0 会提前拦截；返回兼容 NSNumber.doubleValue 的非零比例，图片服务按真实金额门禁，不没收最后零头。
8. 修复原生海报工具返回路径缺失 `shared/image-delivery.isHistoryPreview` ABI：从当前线上模块只追加该真实函数和导出，没有覆盖其他候选海报文案/参考链路。完整工具返回夹具已覆盖，不能再用只返回普通文字的冒烟测试冒充该路径通过。
9. `cost-report.js` 支持明确的负额度调整，不把它当新供应商费用。公开 `/tiers` 仍不返回池金额；没有向公开网页加入 80 元。旧 App 的已鉴权 `/me` 原有金额字段保持兼容，不宣称对抓包客户端绝对保密。

## 切换与回滚

`scripts/apply-cost-budget80-20261118.cjs plan` 只读计划；`apply` 先核对三函数精确已发布时间，在单个 DB 事务内重读账户/15 条流水/四个财务键，历史计数换算、负调整、可信账号政策和四键配置一起提交。当前模式与两个倍率、套餐 JSON 以外的 runtime 字段不得覆盖，保留并行操作者的修改。若客户正在产生新流水，CAS 拒绝，重新只读规划，不能清空余额强行应用。

配置目标：`USAGE_BILLING_MODE=supplier_cost`，`USAGE_COST_MULTIPLIER=1`，`IMAGE_PRICE_MULTIPLIER=1`，原 `TIERS_OVERRIDE.plus.poolCapCny=80`；其他价格/套餐字段原样保留。迁移后旧流水总价加负调整应等于账户本周期成本暂记。

函数回滚使用本目录新鲜 `before-*.zip` 与 `release-cost-budget80-20261118.cjs rollback-bf-...`，先验证当前版本时间/哈希，无后续补丁才允许恢复。**配置/余额切换后不得只回滚函数并机械恢复旧计数**；若有新消费，必须按新旧事件重算并留反向调整审计，禁止覆盖后来的真实用量。没有执行过余额回滚，不声称已演练。
