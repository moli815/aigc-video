# 商业图片复盘与同提示词对照（2026-11-11）

## 状态与问题背景

用户再次否决本地候选：类似PPT、UI/Logo叠层不协调、虚构背景缺乏商业质感。该判断成立。此前的Satori准确排字、源文件哈希与边界测试只证明文字/资产处理的一部分，不证明商业设计合格。`commercial-product-scene.js`候选尚未上线；停止将多换配色或固定布局数量作为审美进步。

本轮不改已寄出App、不改员工端、不部署新候选，不覆盖DSH修改。线上继续已授权的Pro路由。先做三组控制实验，不能把直连Seedream称为App实际链路，也不能把单张胜负归因为模型能力上限。

## 源码根因

1. `commercial-artwork.js`默认分支主动要求独立无字企业场景/插画、排除看板界面，并按3:1规划素材。`commercial-poster-scene.js`又限制主视觉位置；准确排字因此容易退化为资料页。
2. 新的`commercial-product-scene.js`虽使用真实UI与Logo，但依旧由固定矩形分区、字体比例和单张背景决定主要构图。换配色不能替代艺术指导；后加的浅色品牌背景也仍可能成为突兀色块。该候选不作为已验收版本。
3. 原生参考路径的`REFERENCE_CONSTRAINTS`与`multiImageContract(...reference)`要求重做版式；与“保留真实界面内部结构”的义务没有明确分层。需要缩小可变区域，不能把UI内部也视为风格参考。
4. 保真不等于同一hash被放入画面。还要检查完整显示、重采样清晰度、透视、前后遮挡、边缘、光影、品牌对比度及文字避让。此前高confidence定位仍压字，是反例。
5. 背景假不一定是调用了Flash。当前线上Pro已通过路由探针，背景的任务简报、参考资料与构图职责同样影响结果。不能凭一个样例宣称某个开关解锁“满血”。

## 本轮控制实验

材料：同一份1920×1080真实UI与同一份抠出原Logo，字节hash存`outputs/commercial-comparison-20261111/report.json`。完整提示词存`prompt.txt`。

- A：内置imagegen，严格使用相同prompt与两份原件。首次接口网络失败，已进行一次同接口重试；没有静默换模型/CLI，没有伪造基准成品。
- B：当前已部署`/img/image`，临时会员登录、私有素材归属上传、reference/high/16:9；不启用本地候选。真实HTTP200，Pro，86.847秒，已下载`app-live.jpg`。测试账号已删除；1.24是测试账号响应售价，不是客户被扣款，也不是平台发票金额。
- C：Seedream Pro直连，原prompt、原图、2816×1584，移除App附加业务规则；真实HTTP200，98.682秒，已下载`supplier-clean.jpg`。该组只用于隔离链路影响，不冒充App端到端。

B/C均由模型一次生成，没有人工修图后冒充原始输出。原始图必须保留。它们比固定排字样例有更多真实场景，但UI细字、Logo颜色/字样仍被模型重画，不能判为像素保真通过。直连组还把大标题放在数据屏前，遮挡了产品信息，说明删除附加规则本身不足以解决图层问题。

这不是相同随机种子的确定性A/B，不据两图给出统计性胜率。基准图即使更好也要逐项检查；“以基准为准”作为设计验收目标，不豁免真实性与保真。

## 改造方向与验收

1. 商业成品先产完整视觉方案，取消默认“通用背景+固定分栏”决策。保留原图、原文和生成区域的独立身份；不继续叠加更多固定模板。
2. 新增Logo与替换旧Logo分开：替换须先定位/移除旧标识，再处理原件alpha、落位、遮挡。不能全图重绘Logo来求相似；旧包本地`preserve_assets`仍须兼容，不能再贴第二遍。
3. 真实UI进入空间时，使用可核实的屏幕平面与遮挡关系；无法稳定定位不得用自信分数冒充成功。采用明确蒙版或经验证的构图控制，必要时为后端引入独立图像工作进程，不能把Python/GPU依赖强塞Node函数。
4. 用固定原文分别测试：高密度商业广告、真实大屏空间化、Logo添加/替换/非透明源、人物编辑、长上下文改口。逐项保存前置选择、实际发送素材、最终prompt、订单/耗时与原始成品。
5. 验收同时包含：业务事实/文案逐字、真实素材身份/清晰度、图层遮挡/透视、场景真实性、商业视觉。任一失败保留样例继续修；新实现未经真实HTTP、账务、旧包与视觉验收不启用。

当前为新一轮分析与对照测试，不是“全部问题已经修复/已上线”的声明。后续从本目录的原始输出接续，不重复付费跑已完成的B/C。
