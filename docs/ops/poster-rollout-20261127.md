# 海报链路发布与线上复测

## 发布

从生产下发包分别备份 `bf-api` 与 `bf-image`。以公开提交 a92c895 的海报相关代码为更新来源，保留生产依赖及其他账务、审批、鉴权模块。打包核对模块引用、JavaScript 语法、未改文件与依赖 CRC。先更新渲染端，再更新规划端。回读线上包共核对 6,179 与 5,646 个文件。IPA 2026112702 沿用发行包。生产路由沿现有默认版本，灰度由紧凑简报的账号名单控制。[CloudBase 版本管理](https://docs.cloudbase.net/cloud-function/version)

## 线上验证与修正

临时测试账号从冻结版 App 请求字段进入登录、`/api/chat`、受权素材上传和 `/img/image`。第一张默认 3:4 图成功并重放零费，六项服务、品牌、型号、容量、联系方式保留。图中有生成式宣传语，用户允许；后续验收点改为能按要求删除指定位置的文案。

黑白银灰样例首次规划缺少紧凑简报，生成调用尚未开始。源码原先要求前置模型填写选填 `style_source` 才允许新编译分支。用户明确样式现在可直接确定该分支，普通风格仍以规划结果为依据。局部编辑与风格修复用生产成图继续测。测试账号与运行时名单按次清理。改动前双包及回读记录在 `outputs/poster-rollout-20261127`，精简简报可立即撤除名单或恢复上一组文件。阶段状态与实图结果后续追加。

## 局部编辑复测定位

真实 App 请求给出「右上角两行删除，橙色线保留」。前置规划改写成「左上角品牌附近」，并要求连橙线一起删除。供应商调用前已停止。对于这类用户明确指定位置、只删局部且使用最近成图的请求，保留用户原话作为供应商编辑指令，清除模型另外生成的文案。常规创作仍允许主题相关的宣传语。此修复等待实际局部样张复验。
