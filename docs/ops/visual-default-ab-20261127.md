# 默认视觉与用户明确样式的双图试验

## 试验

两组使用同一串对话、同一套定稿和同一柜体及 Logo 参考图，区别在第二组明确给出黑白银灰、低饱和、少装饰和留白要求。使用已配置的 DeepSeek 前置模型实际读图，再用 Seedream 5.5 各成功生成一张 1536×2048。两次规划均恢复更正后的型号、容量和热线，识别出两张图的用途，并作出正确的是否指定风格判断。确认文案直接来自两次规划输出，未用人工补全文案。原话和附件角色作为制作要求，画面文字单独列出。

| 样张 | 验收 |
| --- | --- |
| 默认 | 明亮青绿，其余配色和构图由 5.5 决定。实景延展、柜体主视觉和相关功能图标提升层次。六项服务、型号、容量、热线肉眼核对均出现。 |
| 用户指定 | 黑白银灰、显著留白和细线分区，未添加彩色光效或装饰图标。六项服务、型号、容量、热线肉眼核对均出现。 |

两张都采用了传入的 Logo 图形特征，并把图形与字标从竖排重组成横排。严格同版 Logo 保真需要原件合成。柜体外形相似，细节有生成式变化。样本验证针对设计方向和短中篇文案，不能据此承诺任意长文或素材逐像素正确。

两次 5.5 的返回用量合计 4 张输入和 2 张输出，按火山方舟目录价估算 ¥0.66。两次有图规划台账估算 ¥0.0064，合计约 ¥0.67，实际以供应商账单为准。两次是隔离的模型实验，未更改线上运行版本或客户额度。 [5.5 教程](https://docs.volcengine.com/docs/ark/seedream-5-5?lang=zh) · [官方价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1)

## 实现与回归

在已有 `poster_delivery` 契约中，服务端按前置模型判断的样式来源和用户明确原话决策。短委托与定稿分别传送，附件按现有授权和发送顺序编号。明确样式、允许引用的风格参考或关联项目风格优先。全新创作且用户未指定才加一句主题相关的亮色、密度与场景建议。原始合成、逐字排印、原样直传、重排改版、较长委托和七张以上图册沿用原执行分支。

使用现有 Node.js 模块，新增配置属于已有 `IMAGE_COMPOSITION_POLICY.compactPosterAccounts` 白名单。聊天选择和图像执行两端都检查账号，缺省继续现有路径。未增加供应商、依赖及客户端字段。候选回放复用相同样例并捕获实际 HTTP 请求。覆盖默认、明确风格、前置风格误判时尊重用户原话、跨账号不激活、两图绑定、正文只传一份、原 Logo 保真退出候选以及同请求重放零费用。全量后端 1,055 通过。
