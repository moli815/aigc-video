# 11月3日：流式错误与参展海报质量修复

## 已确认的事实
- 图一展示的是旧App把流内error对象转为字符串的结果：code、message和Unicode转义一起上屏。
- 查到当天13:42的一条同类日志，requestId为6cf16eec-d398-43b3-94fb-88ae19851bf4，耗时8442ms，只记了STREAM_OR_TOOL_ARGUMENTS_INCOMPLETE。调用台账仍是pending。没有截图中的请求编号，不能断言就是同一请求；旧日志也不足以区分上游断流、工具JSON错误等具体触发源，不能猜成欠费或限流。
- DSH下午已修可读错误和主要上游error帧。此次保留其修改，补充流尾error、无终止标志EOF、length截断、content_filter、损坏工具JSON的统一处理。半截工具参数不交给手机执行，错误附requestId；异常结束取消上游读取，使追踪台账能够终结。

## 海报差距与实际复现
图二偏参展行动信息图，图三偏预约广告。前者有目标、优先级、行动安排、筛选与提问；后者多为流程标题、装饰图和重复介绍。仅换模型或追加“精美”无法补出这些内容。

复建一个同类需求（不是已核实逐字相同的客户原始指令）后，发现弱工具schema时前置模型可能返回structured.text字段字典，甚至自创顶层文案字段，而旧App只读typed数组。又复现了模型给19个文本框但出现重叠/越界，旧App将整组退回默认排版的路径。

修复按边界拆分：
1. 商业设计指导v4：先判断攻略/服务广告目的；按用途整理具体内容、视觉层级、素材和准确字段，不靠装饰凑复杂度。按需使用不同布局，用户极简要求仍优先。
2. image-tool-schema.js：在既有图片工具上强化旧包已支持的typed文字契约；保留原有source、preserve_assets及其他工具字段，不增添旧包不会执行的新工具。
3. 图片工具出口把合法字段字典转换成逐项数组，再清理系统补充的来源说明，原文不删减。
4. text-scene.js：有效自由布局完整保留；无效但可容纳的布局按阅读顺序重新放入安全边距，确定性检查覆盖、边界与重叠。不宣称任意长度文案都能放下，不改用户正文。
