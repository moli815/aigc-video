## 源码根因与契约

- `cloudfunctions/bf-api/index.js::handleMemoryExtract` 直接拼接 `dialogue`，没有角色来源隔离；自由文本输出只有类型/长度限制，助手建议、单次报价、明日活动能进入长期记忆。
- `existing.map(...).filter(Boolean).slice(0,30)` 重排原始索引，并截断单条内容；模型越界 update 又转 add。旧 `MemoryService.swift::extractViaHosted` 自身也将非法 update 转 add，因此必须在服务端阻止；仅改 prompt 不够。
- `BossAI/ViewModels/ChatViewModel+Streaming.swift` 当前工作区及 HEAD 的实际触发器每三轮取最近六消息中的用户消息，拼成 `用户：文本`。评测脚本/旧混合输入还会有 `AI：文本`。两种都支持；不能据当前源码断言已寄出二进制的全部行为。
- 现有 HTTP 接口保持 `POST /api/memories/extract`，请求 `{dialogue:string,existing:string[]}`，响应 `{ok:true,ops:[{op,content,index?}]}`。鉴权、503 配置门禁、现有 utility 模型、60秒超时保留。最终 ops 不暴露内部候选 ID。

## 实施方式

- 独立 `memory-extraction.js`：`prepareMemoryInput` → `buildMemoryMessages` → 注入现有模型 transport → `validateMemoryOps`，由 `extractMemories(body, complete)` 编排。
- 仅解析有角色标签的原始文本。助手全文不进入事实候选/模型输入；不把助手建议和“好的”拼成新事实，无法独立确认的指代保守跳过。旧字符串协议没有可信的消息边界，无法鉴别用户在内容中伪造的行首角色标签。
- 用户事实经过中文稳定陈述规则、整段时效/否定/转述/假设筛查，再保留原句。公司名、业务、伙伴关系、固定电话、明确偏好/品牌陈述可入选；不允许模型生成或扩写内容。实际评测脚本的原始口语输入作为正反回归，避免只测人工提示。
- 模型只选择候选 ID 和 add/update；服务端重建原文。未知操作/无证据/补写文本/非法索引均丢弃，绝不退化 add。保留现有记忆的原始位置与空槽位，支持旧 App 最多100条上下文；无效内容不传给模型、不重排索引。
- update 限于同类的本公司名称/颜色偏好；其他宽泛事实只新增。自动 delete 关闭，避免无证据删记录；旧 App 的 ops 字段格式不变，但本候选有意只生成安全的 add/update 子集。
- 入参对话超8000字符、候选超300字符直接跳过，避免截断限定词。最多24候选、最多5操作；去重、标量新陈述优先、同候选/同更新位置不重复。模型异常/非法返回只返回空操作。
- `index.js` 只替换 `handleMemoryExtract` 内部抽取段；写入时逐字节断言函数前后内容未变，保留其他人的已有修改。
