# 商业成图：默认丰富与用户要求优先（候选，未上线）

记录时间：北京时间2026-11-12 16:45接续，17:15整理。不能把本报告或离线测试通过当成商业验收。

## 用户否决与原因

用户否决 `outputs/commercial-readability-20261112/native-layer-retyped.png`。该图采用红白、斜放大屏、大块留白、三栏段落、底部合作说明。真实字体保全539字，只能说明排字改进；视觉仍是资料页，外围小标注仍有伪文字、装饰线冲突，不能商用。

源码层面，旧密度排字路径有固定容器；候选原生路径虽解除它，但设计指导仍停在“层级/丰富/不要PPT”的抽象要求。没有把每段内容绑定到实际图像或信息关系，模型就把全文塞进几栏。再给同构图换字体无法修复这个问题。这里是根据实图与源码的归因，不能推广成所有模型的必然限制。

## 实际候选改动

- `shared/commercial-generation-mode.js`：整理为当前风格优先、内容决策、可执行表达、可读成品四项。默认商业内容充实、有用且多样，明确少字/极简/纯场景时以本轮范围为准；没有固定色板、栏数、风格轮换表。历史广告只借信息组织时不继承其颜色、字体和光效。
- `bf-api/image-tool-schema.js`：仅原生候选生成增加设计简报，说明用途/受众/目标/视觉方向/信息量来源；`visual_map`按稳定文案key选择主视觉、关系、流程、场景、对比、清单、文字或行动入口，表达细节自由。风格与几何布局不绑定。旧客户端仍透传structured，不改二进制。
- `shared/image-design-brief.js`：核验已有文案key全部且仅分配一次，拒绝陌生/重复/遗漏key、空表达及非法简报；默认dense、多于3项才要求不同表达形式，用户明确要求不强加此门槛。编译结果真正进入bf-image供应商prompt；印刷原文增加同key索引，索引不得印在画面中。
- `bf-api/image-task-readiness.js`、`image-tool-repair.js`：有新visual_map时先验证，参数失败仅允许一次重编译，不替换素材或删文案；继承现有未释放/未知结果安全边界。缺新元数据的旧请求保留兼容，不能宣称服务器对任何旧直连请求都强制了新规划。
- `bf-image/index.js`：候选编译传入真实typed文案和原生标志。既有edit/overlay/本机Logo分支维持原契约。前轮PNG候选仍存在，PNG不能保证消除错字或实现原件像素保真。

`surface-typography`和`native-layer-typography`仍是未接HTTP的实验，不能用其清晰字体宣称审美解决。单纯字体实验不应替代原生成品验证。
