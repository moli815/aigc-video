# 千问 Image 3.0 / Pro 迁移：隔离验收，未切客户线路

## 结论与发布门禁

用户目标是降成本，允许3.0标准版与Pro混合路由；前提是不影响已寄出App的功能和质量。19张真实图片（千问16张、Seedream同条件基线3张）后，**不满足全线切换条件**。没有部署云函数、没有改runtime、没有改App/员工端、没有出IPA；不是“已上线但关开关”。候选编译器没有被正式函数require。

千问原生Pro在本轮1083字采购矩阵的主要字段表现优于本轮Seedream基线；标准版便宜，但出现字段关系错误。不能推广成全部任务质量更高。关键阻塞是参考图内容遗漏、编辑画质/指令遵循、素材分支禁字不稳定，以及官方能力边界不同。

## 官方依据与可复用部分

- [统一图片生成/编辑API](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference)：3.0系列最多3张输入；输出面积512²～2048²、比例1:8～8:1；OpenAI与DashScope尺寸分隔符分别是x与*；编辑只能使用direct改写，agent仅支持文生图。模型不接完整多轮聊天，仍需前置模型整理上下文。没有把2.1的10图/透明背景能力算给3.0，也没有臆造Seedream layer_decomposition等价参数。
- [价格](https://help.aliyun.com/zh/model-studio/model-pricing)：北京公开价，3.0标准版输出0.18元/张；Pro按225万像素分界，输出0.25/0.50元；每张输入0.02元。套餐、优惠、最终结算另核，不能把估算写成平台实结。
- [模型概览](https://help.aliyun.com/zh/model-studio/image-model)：复杂文字、编辑为候选能力，不把官方效果宣传当作本项目验收结果。

采用官方HTTP协议，复用现有Node.js运行时、CloudBase SDK、Satori/resvg与字体。没有增加npm依赖、开源权重、第三方素材授权或永久密钥，也没有复制外部项目源码。仅编写请求编译/计量及隔离验证工具。

## 实际源码与新增候选

- bf-image/index.js仍是正式主线，地址及能力表以Seedream为基线。bf-api原有百炼适配不能替代完整主线适配；旧OpenAI通用域名图片路径实测404，原生DashScope路径成功。失败证据保留，没有对未知生图结果自动换供应商重试。
- shared/image-provider-qwen.js是**未接线候选**：两种协议编译、完整有序参考图、显式画布面积归一化而不裁比例、禁止静默截文案/丢图、固定n=1、direct改写、可选无字反向约束；拒绝4图、9:1和原生图层拆分。计量按实际输入数及输出面积，不把图片调用伪装为token。
- shared/model-call-ledger.js本地补充原生DashScope嵌套image数量与size计量。密码、提示词、图片URL/base64不进入台账。该改动也没有部署。
- 原账户归属、历史素材、幂等、会员、准确排字模块没有改动；**没有因为本轮测试宣称旧包全部链路端到端通过**。

## 真实实验及保留失败

总计20个图片接口记录：1次旧OpenAI端点404、19次实际成图。供应商公开价估算8.02元，另有前置聊天调用费用，不混作平台实结。业务/人物均是合成资料；未使用客户原图。完整JSON、OCR、图像在outputs/qwen-image-migration-20261105，HTML为outputs/BossAI-千问Image迁移多场景验收-20261105.html。

1. Pro与标准版同提示词写实人物：均出图，57/69秒，0.50/0.18元。不能用两个独立生成的人像比较“身份保持”。Seedream同提示词基线约25秒；单样本不代表整体速度。
2. 三组真实前置规划：采购矩阵35条/48426字符、1083字定稿；储能展板40条/21544字符、1209字；六模块服务33条/22147字符、1512字。部分早期摘要由夹具提供，不是客户端真实召回。采购/服务的禁词命中包含“旧价作废”“不承诺/不保证”的否定语境，不能当成错误承诺；不过不必要旧价写进画面仍是前置文案问题。
3. 参展攻略A前置模型请求超过200秒，台账有180秒AbortError，未调用图片模型。没有把这个失败算成千问生图失败，也没有声称超长上下文全部通过。
4. 首轮B/D/E错误地将全海报prompt用于素材分支，属于**测试脚本编译错误**；这些图片不作为正式路径证据。随后固定同文案，使用实际commercial-artwork.js与commercial-composer.js重测三组，并对D/E加官方negative_prompt复核。两次正式素材约束复核仍出现带文字的设计说明板/小字，不满足无字素材契约。未继续堆叠第三轮形容词。
5. 1083字原生矩阵，同一文案/视觉prompt对比：千问Pro主要价格、限制及热线目视较好；标准版将旗舰版60账号误标启航版、旗舰版5天实施误标协同版；Seedream基线热线变为400-810-2326（定稿2026）。所以原生模型都不能被当作精确字段关系的确定性渲染器；Pro单例好不等于100%逐字保证。
6. 人物换背景：千问Pro保留了发型、眼镜、红开衫等主要特征，但明显过度锐化/纹理变粗，咖啡厅语义未充分实现。关闭prompt_extend后约34秒，主要视觉问题仍在。相同原图/指令的Seedream基线约31秒，咖啡厅环境与质感更自然；不能只比较衣服颜色宣布人物编辑通过。
7. 双图标准版：实际输入2图，人物参与，但额外生成了平板，超过“只加入人物”的要求。该例不是源图没发到。
8. 三图Pro：供应商usage.input_image_count=3，耗时214749ms，出图有展馆和人物，但**第三图深青工业储能柜没有加入**，0.56元。三份原图完整发送，不是我们此前丢引用的同一根因；仅证明本候选参数下这个场景未通过，不能宣称千问普遍不支持三图。

19张均已目视，OCR只作线索；图像字准确、内容完整、审美、功能兼容分别记录。程序排字的正文正确来自既有排版器，不能计作千问原生文字能力。

## 运维凭据到期与台账恢复

首轮长测试跨过临时运维凭据有效期，部分供应商调用成功但SDK台账写入失败。保留实际返回、计量、requestId与本地图，没有重复出图。通过现有tcb env list刷新运维会话，按当前测试账号和modelCallId恢复4条记录；其中2条生成前insert失败和后续1条基线均有明确恢复记录（详见audit-recovery.json的逐条restored值，以文件为准）。恢复不扣正式客户费用，不伪造已结算金额。脚本补充付费调用前账户可读检查；后续两轮正常记录。所有临时账号已清理，台账保留。

## 成本判断

近30天可见的57次正式成功图片调用：Pro48、Flash9；供应商估算合计29.32元，输入总数11张。只代表现有台账样本，不代表官方30天全账单。

如果全部按2K计、输入量保持不变，70%千问标准+30%千问Pro投影约15.95元，对比样本约省46%；全Pro约28.72元，降幅很小。此投影假定新路由不额外重试、不额外拆图；不能用省钱预测覆盖上面的质量门禁，也不能为了低价把原2K降成1K。

## 后续可执行方案与上线前检查

本轮没有可直接全员启用的配置。若继续迁移，应保持统一内部请求/素材模块，新增独立供应商适配，先完成以下明确工作：

1. 账户隔离的IMAGE供应商策略；普通任务3.0、复杂原生文字Pro。4图、9:1、图层拆分以及未通过的人物/多图编辑保留Seedream能力回退，不静默裁图或丢参考。这样属于“千问为主，Seedream兼容兜底”，**不是纯千问全线替换**。
2. 对密集准确文案继续既有程序排字；无字素材必须有可执行检测/再处理策略，不能仅加negative_prompt后即宣布修好。不得通过删文案、缩到不可读或改掉用户风格来通过。
3. 请求编译/费用快照统一，预算含每一张输入图和最终实际面积。保留同requestId的claim与unknown-outcome，不能在超时不明时跨供应商再扣一次。
4. 使用现有百炼密钥以独立服务端secret字段配置；不把火山IMAGE_API_KEY替换掉；不向App发送凭据。
5. 先真实HTTP旧包契约回归和测试账号canary，再备份当时线上最新版、固定依赖、官方SCF InstallDependency FALSE、上传/下载逐文件核验、健康与403/429/免费重放检查，才考虑全员策略。不能拿本轮直连验证冒充这些检查已经完成。
