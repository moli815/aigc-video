## 三、根因：三个字段名不统一 + 上游契约没走通

### 3.1 bf-api 流式路径的契约没有执行

加了 `finalize_calls_called` / `intent_apply_entry` 两组日志后，线上一次都没有输出——说明
`finalizeImageCalls` 在流式路径没有被调用。画布能稳定 3:4 是模型自己选的，不是规范化生效。

本地用同样参数调 `intentContract.apply` 是正常的（182 → 578 字），所以问题在链路调用，不在契约本身。
这一层**尚未定位**，属于遗留问题（见第六节）。

### 3.2 模型给文案的字段名有四种写法

真实抓到的四种形态：

| 形态 | 例子 |
|---|---|
| `role` + `text` | `{role:"title", text:"栗香上市"}` |
| `type` + `text` | `{type:"title", text:"小雪"}` |
| `type` + `content` | `{type:"title", content:"今日小雪"}` |
| 对象（顶层键） | `{title:"…", labels:[…], bodies:[…], contact:"…"}` |

原来的解析只认 `role` + `text`，另外三种全部落空：
- `role` 缺失 → 标题被降级成普通说明，底部信息带消失；
- `content` 缺失 → 整条文案被过滤掉，表现为**零文字**。

### 3.3 修法：bf-image 侧兜底，不依赖上游

`bf-image` 收到 `structured` 后自己判断：如果最终提示词里没有「逐字照写」标记，
就用 `normalizeCopy` 把文案解析出来，自己追加一遍契约。上游已经追加过就跳过，不会重复。

同时把解析函数统一：

```js
function textOf(item) {
  const v = item.text != null ? item.text : (item.content != null ? item.content : item.value);
  return String(v == null ? "" : v).trim();
}
// role 也兼容 type
{ role: String(b.role || b.type || "body"), text: textOf(b) }
```

四种形态实测全部解析正确：

```
content字段 → 4 条: title:今日小雪 | subtitle:科技·安全 | label:智慧安消 | body:风险早发现
text字段   → 3 条: title:栗香上市 | label:欧包 | body:¥18
对象形态   → 5 条: title:开业大吉 | label:A | body:1 | label:B | body:2
字符串     → 3 条
```

## 五、仍然存在的风险

**价格是模型补的**。客户 `structured` 里没有价格，图上却出现 ¥2,380 / ¥1,280 / ¥850 等六档报价——
模型把「产品卡」模板套成了电商价目表。对这类客户（卖解决方案、不卖单台设备）是硬伤，必须处理：

- 短期：提示词里加「没有提供价格时不要虚构价格、不要画价格位」；
- 中期：结构化层的 label/body 明确区分「能力」与「商品」，能力型条目不出价格。
