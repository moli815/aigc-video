# 对话风格与交付意图审查（2026-11-10）

## 目标与范围

用户要求降低模板化、空话和不听指令的表达，让体验向自然、直接、上下文连贯的 ChatGPT 风格靠近。这里做指令与专家工作流优化，不是训练模型权重，也不声称获得 ChatGPT 同等能力。不修改 App/员工端，不出 IPA，不改变模型、计费、会员或图片渲染器。

## 源码根因

1. `BossAI/Models/Expert.swift: ExpertSkill.promptBlock` 将技能包以“必须遵循的工作流”发给模型；短视频模板要求固定三角度、三钩子和完整分镜。它是方法模板，不应该覆盖用户明确的纯文案格式。
2. `bf-api/index.js: RUNTIME_SPECS.CHAT_RULES` 允许固定开场、先共情、收尾邀约，缺少更具体的交付仲裁。此前的 `assistant-guidance.js` 只有身份与工作量说明。
3. `commercial-image-guidance.js: isCommercialTask` 对展会、展板等词直接命中，写口播或补背景也被塞入海报设计指导，造成不同能力提示竞争。
4. 客户纠正格式后，模型仍把先前分析框架和自己的推测当作写作素材。仅添加“自然/专业/高级”不能解决事实与意图错误。

## 本轮修改

- 新增 `assistant-style-policy.js`：交付格式优先于默认模板；补资料延续原任务；只改指定段；直接交成品；不添选题、多版本与邀约；不编客户原话/订单/数据；必要安全提示和工具继续执行。
- `assistant-guidance.js` 沿用身份标记的幂等注入，将表达策略放在独立模块。只处理服务端注入的 system 块，保留用户消息、附件、工具结果、品牌原文与 JSON，不做输出字符串删词。
- `CHAT_STYLE_POLICY` 配置支持 enabled/instructions；**默认关闭**，因为候选未通过事实验收。未来完成新验收后才可显式开启；false 仅撤回候选表达策略，身份、真实性、工具与会员规则保留。自定义 instructions 最大 6000 字符。
- 修改 `CHAT_RULES` 默认第 6/8/9 条，取消习惯性开场、机械共情和结尾邀约。
- 商业图指导明确排除纯口播、脚本、只补说明，以及口播任务中的展板背景补充；后续明确要图片时仍可正常进入图片指导。
- 仅通过 `tuneExpertCatalog` 更新 general、short_video 的内容字段；ID、权限工具、默认导出格式、其他专家和管理员设置保留。更新云端目录时使用事务，自增版本，防止被默认种子重刷。
- 同步更新 `experts.json` 的两个默认模板，避免管理员“恢复默认”后又回到原来固定三角度/分镜；线上目录版本 6 高于种子版本 4，不会覆盖其他专家的管理员编辑。

## 后续服务端工作：事实约束的成品审查（未实现）

三轮补提示仍出现同一类现场故事补写，停止继续堆风格词。影响是商业文案的可信性，不能用“更有感染力”掩盖，也不能靠替换几个关键词冒充完成。

下一步应隔离实现事实简报 → 成稿 → 独立审查，先在离线合成场景验证，再考虑上线：

1. 从本账号真实用户资料/附件与检索证据整理可引用事实；助手自己写的故事不是证据。保留原始依据及来源类型，不能从品牌名称猜业务。
2. 成稿不新增用户经历、交易、认证、理赔与效果承诺；价值解读需与已有能力区分。
3. 独立审查按“具体断言—证据”对照，不只用正则数关键词；针对没依据的片段修订，仍不通过时自然说明缺口。
4. 不能在流式文本已展示后再声称它已审查。需设计兼容旧 App 的首字节/总时限、工具调用旁路、SSE 错误与结束帧、unknown-outcome 和费用台账，避免审稿重复付费、误把工具结果当正文。
5. 新增校验要覆盖纯成稿、附件补充、上下文纠正、完整方案、JSON、局部修改、文档/图片工具、必要安全提示；先账户隔离验收，不以这份计划冒充已经实现。

这是服务端质量待办，不需要默认归入 IPA。本轮不会把未完成的审稿流程接到客户线上。
