# 海报文字契约与出图审计（2026-11-21 ~ 11-22）

> 这份文档记录 11-21 至 11-22 两天内对海报出图链路的全部改动、每项的根因、验证方式和已知限制。
> 目的：任何人接手时不用翻聊天记录就能知道「为什么这么写」。

## 一、背景

客户侧反馈集中在三类：

1. 海报上的小字大面积崩坏，出现「北海址小止眨·栗子现 40y」这类伪文字；
2. 图片排版生硬、纯白底、没有元素，像 Word 文档；
3. 客户端偶发报「输出尚未完成」「画布比例与要求不同」，一张图都拿不到。

前两类是出图链路的问题，第三类是契约抛错杀流 + 画布未锁定。

## 二、改动清单

### 2.1 提示词契约（`cloudfunctions/bf-api/prompt-contract.js`，新增文件）

这个文件此前**只存在于线上部署包**，从未进过仓库。工作内容是：把模型写的画面描述 + 结构化文案，
拼成发给 Seedream 的最终提示词。

关键设计（每条都对应一次实测）：

| 设计 | 根因 |
|---|---|
| 主标题写进**画面描述开头**，标注「品牌既定文案，逐字照写」 | 单独占一行时，模型会为画面氛围改写标题：「栗香上市」→「秋天的栗香」「用一颗面包温暖每一天」 |
| 风格段**永不可省**（含精简版 `STYLE_MIN`） | 总长超限时会降级到 minimal 档，把「画面 + 风格」整段丢掉 → 纯白底、无元素 |
| 价格**粘进名称块**：`「AC-2000 双目球机 ¥1280」` | 拆成两个引号块时，六款设备的报价会被整体省略 |
| 卡片说明 ≤14 字且六张长度接近 | 20 字时必出伪字；长度差异大时六卡高度不齐 |
| 底部信息带写成**一条**指令 | 写成「左段 / 右段」时，模型会做两行，同一组电话印两遍 |
| 禁令点名「不写超过 20 字的长段落」 | 只说「不出现未列出的文字」时，模型会自己补 200 字品牌故事，全是伪字 |
| 禁令点名「不写『二维码空位』这类占位说明」 | 模型会把占位标注当正文印出来 |
| 网格系统整句：同一行卡片等高、同栏等宽、元素对齐、间距统一 | 来源于社区方案（StartAI《Seedream 5.5 海报提示词公式》：「严格符合网格系统布局规范」）；不加这句时卡片高低不齐、栏宽不等 |
| 「卡片左侧画示意图或图标」 | 没有产品素材时，模型会把卡片做成纯文字块 |
| 构图「主视觉在上 → 渐隐过渡 → 浅色信息面」 | 硬边横切会割裂；满版场景会把文字压在杂乱背景上 |
| `MAX_LEN = 1100` | 1020 装不下 full 档（实测 1076）会被迫降级；900 会丢掉画面与风格 |
| `expand` 短句阈值 6 → 3 字 | 「质保10年」只有 5 字，被当碎片过滤掉，硬参数丢失 |

### 2.2 意图契约（`cloudfunctions/bf-api/intent-contract.js`）

- 参考冲突改为**收敛**：本轮有附件就以附件为准，丢掉历史原图项，不再抛 `IMAGE_REFERENCE_CONFLICT` 杀流。
- 海报判定补齐 `labels / bodies / products / items` 等对象形态——只认 `text` 数组时会漏判，
  漏判的后果是画布不锁、排版契约不追加。
- 海报画布规范化：用户没明确要求比例时统一锁 **3:4**。模型自己会挑 2:3 / 4:5，客户端按请求比例校验就会判「比例不符」并丢弃整张图。
- 兜底：契约处理任何异常都 fail-open，保留原 prompt，不让整条 SSE 中断。

### 2.3 出图审计（`cloudfunctions/bf-image/shared/number-audit.js`，新增文件）

出图后用视觉模型（qwen3-vl-plus）回读整张图，做两级校验：

**数字/规格校验**：从提示词抽价格、克数、百分比、年限、层数，比对 OCR 结果。
先按原样比，再退一步只比数字（容忍 `4980 元` 与 `¥4980` 写法差异）。

**结构校验**（决定要不要重跑）：

| 检查项 | 判据 | 为什么用这个判据 |
|---|---|---|
| 主标题 | 缺失即重跑 | 品牌资产 |
| 电话 / 署名 | 缺失即重跑 | 商业海报必需项 |
| 卡片数 | **价格缺失 ≥2** 即重跑 | 价格只出现在卡片里，是卡数的可靠代理；产品名会被写进别的区域，OCR 读到就误判「齐全」 |
| 编号重复 | 同一编号（S1/S2）出现 ≥2 次即重跑 | 六阶段被排成 S1/S2/S3/S3/S4/S5 时条目实际少一个，而这类场景往往没有价格 |
| 署名比对 | 只比第一段中文品牌名 | OCR 通常只抄品牌名，不抄英文和地址，整串比会误报 |

重试**只发生一次**，且只在硬伤时触发；「说明被润色」这类软问题不重跑。

### 2.4 出图主流程（`cloudfunctions/bf-image/index.js`）

- 客户端没给 `aspect_ratio` 时，从提示词推断构图并锁定比例（此前只传「2K」，画布由上游随机选，实测出过 0.4 / 0.667 / 0.75 三种）。
- 接入上面的审计；`NUMBER_AUDIT_MODE=off` 可关闭，`STRUCT_AUDIT_MODE=off` 可只关结构校验。
- 视觉配置在 bf-image 侧缺失时，回退读同名环境变量（原来只配在 bf-api，导致校验永久跳过）。

### 2.5 素材超限文案（`cloudfunctions/bf-api/domains/foundation.js` + `shared/asset-store.js`）

旧文案「这次内容没有完整保存，请检查输入后重试」既不提体积也不提上限，用户只会拿同一张图反复重试。
现在返回：「这张图约 30MB，超过 24MB 上限；请压缩后或换一张再发。」

## 三、验证方式

### 3.1 本地提示词自检（不花钱，改动后必跑）

```bash
node scripts/verify-prompt-contract-20261122.cjs
```

检查 12 项：段落齐全、风格段未降级、网格与示意图要求在、卡片数、价格与名称同块、说明长度、
底部信息带唯一、无重复段落、普通配图不被污染、画布锁 3:4。
**不通过就不要出图**——这脚本当场抓出过 5 个跑图也看不出来的问题。

### 3.2 单元测试

```bash
node --test --no-warnings tests-backend/number-audit-20261122.test.js \
  tests-backend/prompt-contract-20261121.test.js \
  tests-backend/reference-conflict-20261122.test.js
```

### 3.3 真实场景回归

```bash
node scripts/preflight-refguard-20261122.cjs     # 接口 6 项
node scripts/preflight-overlay-20261121.cjs      # 客户端链路 3 项
```

### 3.4 真实行业出图（消耗额度，谨慎）

```bash
node scripts/multiscenario-test-20261121.cjs --only=security
```

2026-11-22 实测两例：
- **安防（47 轮对话）**：六款设备三列两行等距对齐、每卡型号参数产品图齐全、电话正确 → 达交付级；
- **少儿编程（45 轮对话）**：视觉质量好，但阶段被排成 S1/S2/S3/S3/S4/S5（少一档）→ 直接催生了 2.3 的「编号重复」判据。

结论：**素材决定上限**。有对应产品实拍图时六条目能全对；没有图时模型把精力花在装饰上，条目容易漏。

## 四、已知限制（不要对外承诺）

1. **卡片说明会被润色成卖点**：`栗子泥 40 克` → `栗子奶油`。提示词压不住，只能靠审计报告逐条列出缺了什么。
2. **价格可能被整体省略**：已用「价格粘名称」缓解，但不是 100%。
3. **条目多且无素材时会合并条目**：现在靠编号重复判据兜底重跑一次。
4. **「对称 + 六条目 + 说明 + 配图」四件同时要，Seedream 单张做不到**——它的文字/元素预算有限，需要服务端接管文字层。
5. **长文全文排版**代码已就绪（`poster-overlay.js` 的 `longformTree`），但分流未接。

## 六、环境变量

| 变量 | 位置 | 说明 |
|---|---|---|
| `NUMBER_AUDIT_MODE` | bf-image | `off` 关闭数字校验，默认 `report` |
| `STRUCT_AUDIT_MODE` | bf-image | `off` 关闭结构校验与自动重跑，默认 `on` |
| `CHAT_API_KEY` / `CHAT_MODEL_VISION` / `CHAT_PROVIDER_BASE` | bf-image | 视觉审计用，与 bf-api 同值（未轮换密钥） |
